# intent-chain 毕业考判卷报告（2026-07-26 ~ 07-27）

> 首次真实用户检验：真人驾驶、真实商业需求、无模拟成分。判分方 Fable 5，考中不插手流程（仅答疑机制问题），所有关键结论经判分方独立复跑核验，不采信执行侧自报。

## 一、考试设置

- **考题**：EnterpriseMatchHub（企业信息撮合平台）——正是 2026-06 引发 intent-chain 立项的那个项目。当年直接从聊天进开发，产出三大质量事故：原型没当验收标准、"金刚区"黑话直接上界面、FRANCHISE/TRANSFER/COOP 英文码直出。本次链路带着为它而建的三个机制（设计标准、术语表、验收路径）迎接正主回归。
- **材料**：题目一句话（"1:1 还原 excel 全部功能点，页面以 prototype 为准，不能随意发挥"）、61 行功能需求表（APP 企业端 12 模块 + 后台 15 模块）、57 文件的原型目录（11 张可点 HTML + 30 张设计稿 PNG + brand-spec + fig-alignment）。
- **配置**：用户在考场目录独立会话亲自驾驶；执行模型 Sonnet 5（high 档，与全部历史冒烟/模拟同口径）；九个 skill 与仓库 c72ffd7 零差异干净安装；考场根目录放置律刃 v3.4。
- **用时**：一晚（7-26 晚开考，7-27 凌晨交卷），中段 14 个工单由用户主动要求切换为并行执行。

## 三、三道历史错题终审

### 错题 1：原型未当验收标准 → **通过（满分表现）**

- intent.md §12 把双素材立为验收基线：D01（11 张已建 HTML）+ D02（30 张 PNG 设计稿）；连"14-19 张页面只有 PNG 没有 HTML"这个材料缺口都在 Phase 1 被挖出并转为正式决策（"按设计稿新建 HTML"）。
- 实施层两次原型/需求冲突均被上报用户拍板而非静默处理：①excel 要密码登录 vs 原型只有验证码（用户定"验证码为主+可选密码"）；②excel 要求"所属类型"字段 vs 原型漏画（按 excel 补上，styling 沿用原型，标注"文档化的主动补充，非随意发挥"）。
- **两个月前的翻车方式就是在这类时刻自由发挥；本次全部举手。**

### 错题 2：黑话直接上界面 → **未通过（部分进步，系统性逃逸）**

- 进步面：术语表正确登记（金刚区→"首页功能入口"等 5 条），PRD/工单传递检查全绿。
- 失守面：**登记了翻译但全线未执行替换**。逃逸路径完整：anchor 能力表命名即带原词（C06"金刚区类型展示"、C30"金刚区分类排序"）→ PRD/工单合法繁殖 → 代码（含企业端 home.vue）→ 界面文案（后台页标题"金刚区分类排序"）→ verify-record 自身也在使用该词 → 终审无感放行。
- 根因：所有校验器只查"术语表存在、被引用"，**没有一站查"原始术语不得出现在下游产物"**。结构全对、语义穿透，属评测体系定义的标准逃逸。修法见第五节（已定双层机械检查方案）。

### 错题 3：英文码直出界面 → **通过（标准工程模式）**

- 文档层：intent/prd 全文零残留。
- 实现层：英文码仅存在于 `app/src/utils/category.ts` 内部映射表（`franchise: "招商加盟"`），页面层零裸码——代码归代码、文案归文案，恰是该问题的教科书解法。

## 四、过程中的门禁与纪律表现（正面样本）

1. **执行者对子代理执行了"汇报只作线索"**：并行 workflow 结束后，编排者不依赖子代理自报，亲手复跑 288+46 全量测试、双端类型检查、真实编译——仓库核心纪律在委托链上自发下传一层。
2. **verify 抓住部署级真问题**：后台静态页无反代，实走时如实区分"测试环境通过"与"部署后可用"（并主动披露自己用 Playwright 拦截完成验证的脚手架事实），升格严重性、给最小修复方案、经用户确认修复。
3. **5 条已知限制如实披露**，无一隐瞒；4 条"合法通过验收"的判定依据（Then 字面范围）如实呈现，并把"是否纳入范围"还给用户（正确路由到新工单/impact）。
4. **确认门禁**：full 档确认、17 工单结构确认、修复决策均走用户显式确认；节奏协商（"17 工单怎么推进"）是值得的提问的范本。
5. **并行即兴编排**：用户要求提速后，执行者基于工单 Blocked by 依赖自行分四波并行（18 代理零失败、4 道波间集成关卡全绿）——证明链路结构（依赖标注+垂直切片+持久记录）足以让并行安全，无需官方编排机制。
6. **正式定档用真实计数**（保留 48 能力核对四条件），两段式定档设计生效。

## 六、结论

**毕业考：通过（9 项发现随卷附上，其中 1 门单科不及格）。**

- 链路的核心承诺兑现：真实用户 + 相对弱模型，一晚交付可运行的双端全栈系统，48 个保留能力全程可追溯，两处需求冲突和一个部署缺口在流程内被抓住并经用户决策处理，无造假、无静默扩权、无隐瞒。
- 当年三大事故：两个被机制根治，一个（术语落地）从"无知"进步到"登记未执行"，且本次考试精确定位了它的完整逃逸路径和双层修法——**这条逃逸本身就是本场考试最有价值的产出**。
- 体系的元循环也被验证：考试同时产出 9 条改进输入，其中 4 条在考试进行期间即完成修复入库——"失败是资产"的循环速度快于考试本身。

**判分方声明**：本报告的校验结论（chain_validate 7/7、术语/英文码 grep、源码检查）均为判分方独立执行；确认次数为未测项，如实标注；执行侧自报仅在与独立核验一致时采信。
