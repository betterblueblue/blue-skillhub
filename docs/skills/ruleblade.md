# 律刃 RuleBlade（行为规则）

> 一组写给 AI 编码助手的常驻行为规则，按模型能力分成两份：完整版给 DeepSeek V4.1 Flash 这一档的模型，精简版给 Opus 5.5、GPT-6 Astra 这一档的旗舰模型。管的是判断：先弄清目标和上下文再动手、少猜、该停就停、对用户说人话。

运行：`/ruleblade`（手动触发，装一次长期生效）｜规则正文：[完整版](../../skills/ruleblade/CLAUDE.full.md)、[精简版](../../skills/ruleblade/CLAUDE.lite.md)

## 它做什么

- 先问你在这个项目里主要用哪个模型，再选一份装进项目根目录：旗舰模型装精简版，其他模型或拿不准时装完整版。Claude Code 项目写 `CLAUDE.md`，Codex 和 DeepSeek Harness 写 `AGENTS.md`。
- 规则覆盖：先思考再编码、上下文先行、简单优先、精准修改、目标驱动执行、改前确认语义约定、测试策略、按影响面分档、防止过度优化与评审扩张，外加面向用户的中文表达规范。精简版把这些压成 6 段原则。
- 目标项目已有同名文件时不覆盖。里面有旧版律刃，就问你要不要换成新版；没有就追加或提示你合并，冲突处由你决定。

## 什么时候用

- 新接手的项目，第一次让 AI 干活之前装一次。
- 已有 `CLAUDE.md` / `AGENTS.md` 的项目，合并进去；里面是旧版律刃的，重新运行 `/ruleblade` 升级。
- 主力模型换了档，比如从 DeepSeek 换成 Opus，重新装另一份。
- 它和专项技能是分工关系：律刃管通用编码行为，IntentAnchor / Pathfinder / ImpactRadar 管各自的流程；单独使用也成立。

## 常见问题

**为什么要分两份？**
强模型和弱一点的模型在同一份规则下出的问题方向相反：弱一点的模型需要把检查动作和次数上限写具体，强模型照着这些写死的步骤反而会过度检查、过早停下来请示。在 DeepSeek V4.1 Flash 上实测，两份的通过率一样，都是 39/39；但精简版多花约 29% 的 token，所以非旗舰模型用完整版。

**会不会让小改动变得很啰嗦？**
完整版按影响面分档：新建文件这类生成型任务自查最多 2 轮；只有动数据库、接口、权限、状态机或跨多个模块时，才要求先把影响范围查清楚。实测改错别字这类任务，两份的回复都只有一两句话。

**和 ImpactRadar 的门禁重复吗？**
不重复。律刃约束"动手前的判断习惯"，impact 的 `确认 Step N` 约束"写操作授权"：前者是常驻素养，后者是高风险流程门禁。

**规则会不会过时？**
版本化管理（当前 v5.0），每轮大改都有实测记录。v5.0 的记录见 [TASK_V5_VERIFY.md](../../skills/ruleblade/TASK_V5_VERIFY.md)；精简版还没在 Opus 5.5、GPT-6 Astra 上实测。

## 用对了是什么样子

- 项目根目录的 `CLAUDE.md` 或 `AGENTS.md` 里能看到规则正文，agent 每次会话都遵守。
- AI 动手前会主动说明假设和歧义，而不是猜一个方向闷头写。
- 你说"再优化一轮"但没说改哪里时，它会先说明已经达标，再列出具体可改的点让你选。
- 测试和文档对不上时，它会先把矛盾告诉你，而不是改掉一边让测试变绿。
- 向你汇报时说的是"哪条测试失败了、第一个错误是什么"，而不是"可能环境有问题"。
