# 律刃 RuleBlade（行为规则）

> 一组写给 AI 编码助手的常驻行为规则：8 条编码规则、1 条评审与迭代纪律、1 条中文表达要求。管的是判断——先弄清目标和上下文再动手、少猜、对用户说人话。

运行：`/ruleblade`（手动触发，装一次长期生效）｜规则正文：[skills/ruleblade/CLAUDE.md](../../skills/ruleblade/CLAUDE.md)

## 它做什么

- 把规则文件安装进目标项目根目录：Claude Code 项目写 `CLAUDE.md`，Codex 项目写 `AGENTS.md`（同一份内容）。
- 规则覆盖：先思考再编码、上下文先行、简单优先、精准修改、目标驱动执行、改前确认语义约定、测试策略、按任务规模缩放检查范围、防止过度优化与评审扩张，外加面向用户的中文表达规范。
- 目标项目已有同名文件时不覆盖，追加或提示用户合并，冲突处用户决定。

## 什么时候用

- 新接手的项目第一次让 AI 干活之前，装一次。
- 已有 `CLAUDE.md`/`AGENTS.md` 的项目，合并进去。
- 它和专项技能是分工关系：律刃管通用编码行为，IntentAnchor / Pathfinder / ImpactRadar 管各自的流程；单独使用也成立。

## 常见问题

**会不会让小改动变得很啰嗦？**
第 8 条按规模缩放：20 行以内的低风险改动只保留必检项；涉及数据库、接口、权限、状态机或多模块时才要求完整检查。

**和 ImpactRadar 的门禁重复吗？**
不重复。律刃约束"动手前的判断习惯"，impact 的 `确认 Step N` 约束"写操作授权"——前者是常驻素养，后者是高风险流程门禁。

**规则会不会过时？**
版本化管理（当前 v3.4），每轮大改都有跨模型稳定性复测记录，见技能目录内的 README。

## 用对了是什么样子

- 项目根目录的 `CLAUDE.md` 里能看到规则正文，agent 每次会话都遵守。
- AI 动手前会主动说明假设和歧义，而不是猜一个方向闷头写。
- 向你汇报时说的是"哪条测试失败了、第一个错误是什么"，而不是"可能环境有问题"。
