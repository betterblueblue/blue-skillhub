# IntentIssues（拆分工单）

> 把 PRD 拆成独立可抓取的工单。每个工单是贯穿所有集成层的垂直切片，不是按层分的水平切片；工单自动引用验收路径编号，输出前机械检查所有路径被覆盖。

运行：`/intent-issues`（手动触发）｜技能本体：[skills/intent-issues/](../../skills/intent-issues/)

## 它做什么

- 按垂直切片（tracer bullet）拆分：每个工单交付一条贯穿 schema、API、UI、测试的完整路径，做完就能独立演示。
- 偏好多个薄切片，而不是少数厚切片；工单分为 HITL（需人工交互确认）和 AFK（可自动完成）两类，优先 AFK。
- 工单的 Acceptance criteria 引用涉及的验收路径编号（如 `[P01]`）；输出前自动检查 INTENT.md 第 14 节的所有验收路径至少被一个工单覆盖，漏了会列出来要求补充。
- 工单间的依赖写成 `Blocked by`，开发阶段据此排顺序。
- 轻量档允许单工单直行（一个 AFK 工单覆盖全部路径），但路径覆盖检查不降级。

## 什么时候用

- intent-design 完成之后、开发之前。
- 前置条件：INTENT.md、PRD、architecture.md、design.md 四者齐且通过校验。
- 不需要用：单个小改动（直接做或走 impact 的 light 档）。

## 常见问题

**垂直切片和水平切片差在哪？**
水平切片是"先把所有表建完，再写所有接口，再写所有页面"——做到一半什么都没法演示；垂直切片每个工单做完都能跑通一条用户路径。

**为什么工单不按验收路径拆？**
工单是实施单元，路径是验收单元；两者粒度常常不一致。工单引用路径编号，保证每条路径最终被实施覆盖。

**"单工单直行"是不是等于不拆？**
小项目确实一个工单走完，但验收标准仍逐条引用路径编号、涉及模块仍须列全，覆盖检查照跑。

## 用对了是什么样子

- `issues_validate.py` 校验通过，路径覆盖检查没有遗漏项。
- 每个工单单独拿出来能理解、能开发、能演示，不依赖"先做完别的所有工单"。
- 每条验收路径都能指出自己被哪些工单覆盖。
