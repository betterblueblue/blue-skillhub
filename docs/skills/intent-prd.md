# IntentPRD（意图到产品需求）

> 读取 `INTENT.md`，生成一份结构化 PRD；能力表、验收路径、设计标准、术语表从意图文件原生引用，不靠交接 prompt 注入。

运行：`/intent-prd`（手动触发）｜技能本体：[skills/intent-prd/](../../skills/intent-prd/)

## 它做什么

- 把 `INTENT.md` 转化为 `prd.md`，章节映射是固定的：一句话意图→问题陈述、保留能力→用户故事、验收路径→验收标准、性能/安全要求→实现决策，推迟与放弃→范围外。
- 每个保留能力至少对应一个用户故事；验收标准直接引用意图文件里的验收路径编号。
- 轻量档允许薄写法（用户故事每能力一行、实现决策一行表），但必需章节和结构不变，`prd_validate.py` 照常运行。

## 什么时候用

- intent-anchor 完成之后、技术方案设计之前。
- 前置条件：`INTENT.md` 已通过 `intent_validate.py`，且没有 `待确认` 项。
- 不需要用：没有走意图链路、手里已有完整 PRD 的项目。

## 常见问题

**能跳过 PRD 直接开发吗？**
链路内不建议。PRD 是 intent-dev 验收的依据之一，跳过会让工单验收标准失去上游锚点。

**INTENT.md 里还有"待确认"项能开跑吗？**
不能。会停止并提示先回 intent-anchor 把冲突裁决掉。

**和直接让 AI 写一份 PRD 有什么不同？**
区别在约束的传递方式：这里的 PRD 被校验器检查章节结构，且下游 intent-issues / intent-dev 会核对 PRD 与 INTENT 的一致性，"确认过的东西下游不能偷偷丢掉"是被机械检查的。

## 用对了是什么样子

- `prd_validate.py` 校验通过。
- INTENT.md 的每个保留能力都能在用户故事里找到对应条目。
- 验收标准一节逐条引用了验收路径编号，没有自由发挥的新增范围。
