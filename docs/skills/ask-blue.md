# ask-blue（路由）

> 不知道该用哪个技能时问它。按你的处境指到对应入口，说清楚为什么，以及用完之后下一步去哪。

运行：`/ask-blue`（手动触发）｜技能本体：[skills/ask-blue/](../../skills/ask-blue/)

## 它做什么

- 把仓库的技能组织成两条主线：从零做新项目的 intent-chain 八件套（anchor → prd → design → visual → issues → dev → adversarial → verify），和改已有系统的 pathfinder（可选）+ impact。
- 按处境指路：模糊想法、陌生仓库、明确改动、UI 风格要求、交付前验收、装行为规则、图片输入等，各有一条入口和后续去向。
- 说明插件外的东西：`prompt/` 工具箱、whydump、eval 体系在 GitHub 仓库里，不随插件分发。

## 什么时候用

- 记不住十几个技能各自管什么，直接问"我现在这个情况该用哪个"。
- 处境落在两条主线之间（比如"在已有系统上加一个大功能"），它先问清从零建还是改现有，再指路。
- 已经知道要用什么时不需要它，直接调目标技能。

## 常见问题

**它和 README 里的场景表什么关系？**
同一张决策逻辑，README 的表给人看，ask-blue 给 agent 看——装了插件后不用翻网页，在会话里问就行。

**它会替我选流程吗？**
指路会给出推荐和理由，但两条主线之间的选择（从零建还是改现有）会先问你，不替你猜。

**为什么不做成模型自动触发？**
路由是"问路"性质；模型自动猜你的意图反而容易打断你正在做的事，所以保持手动调用。

## 用对了是什么样子

- 一问一答拿到：入口技能名、一句话理由、用完之后去哪。
- 顺着指的路线走，不会在中途发现"其实应该先跑另一个技能"。
