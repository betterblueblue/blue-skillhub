# Pathfinder（项目领航）

> 刚接手陌生项目时做一次只读的全项目摸底：技术栈、核心功能、架构分层、入口、数据模型、怎么跑起来、风险区域在哪。产出的项目地图供 ImpactRadar 做导航上下文。

运行：`/pathfinder`（模型可自动触发）｜技能本体：[skills/pathfinder/](../../skills/pathfinder/)

## 它做什么

- 全程只读：不改任何项目代码，唯一写入是自己的地图 `change-impact/_project-map.md` 和事实文件 `facts/*.json`。
- 结论标注可信度：【已核实】有工具证据、【推断】从命名或结构猜测——绝不把推断写成事实。
- 先量体量再定预算：小仓细扫、大仓按预算分档深挖，没挖到的显式列进"未覆盖项"清单，可以"再挖 X"继续。
- 事实层由脚本产出确定性数据（文件统计、Git 热点），地图写入前过 Script Gate 校验（`pf_validate.py` exit 0）。
- 与 impact 的分工：pathfinder 回答"这项目是什么样"，impact 回答"这次变更影响什么"。地图是 impact 的可选加速器，不是前置必跑项。

## 什么时候用

- 刚接手或被丢过来一个陌生仓库，想知道"这是个啥、从哪下手"。
- 动手改之前想先建立项目认知，让后续 impact 分析有现成的导航层。
- 不需要用：已经熟悉的项目（直接 impact）；新项目（没东西可摸）。

## 常见问题

**它会改我的代码吗？**
不会。只读纪律是硬规则，Write/Edit 只用于产出它自己的地图和 facts 文件。

**超大仓库扫得动吗？**
先统计文件数定预算档位，大仓不硬扫；用户关注重点决定哪片挖得更深，但不裁剪覆盖广度，未挖深的如实声明。

**地图会过期吗？**
impact 消费地图时有过期检测（按 Git 状态比对）；也可以随时"刷新"重跑 facts 比对差异。

**结论能直接信吗？**
地图上每条结论都带可信度标注；带【推断】的条目，impact 使用时会重新核实。

## 用对了是什么样子

- `pf_validate.py` 退出码为 0，facts 文件齐全。
- 每条结论都有【已核实】或【推断】标注，找不到证据的写进了未确认项。
- 未覆盖项清单诚实列出——没看过的部分不会被写得像看过一样。
