# ADR-002 历史清理为什么用 git filter-repo

日期：2026-09-05　状态：已采纳

## 决定

发现公开仓库中两份含真实个人信息的会话转写（blue-interview-log/ 与 docs/archive/ 下各一份，含真实姓名共 12 处）后，采用 `git filter-repo --invert-paths` 从全部 486 个提交中抹除，并 force push 重写远端历史。

## 为什么

普通的 `git rm` 只让文件从最新版本消失，旧提交的 SHA 直链仍能访问内容——对公开仓库来说泄露只是"看不见"而非"不存在"。历史重写是唯一能彻底移除的手段。

## 代价与风险（已接受）

- 全仓库提交哈希改变，此前的 clone/fork 与远端失配。
- GitHub 侧缓存视图可能残留旧提交，需联系 GitHub Support 清理。
- 仓库为个人项目、无外部协作者，force push 的破坏面可控。

## 备忘

- 处理前先把涉事文件备份到仓库外，再执行重写（filter-repo 会连工作区文件一起删）。
- 同批处理了测试用 `.env`（假数据但属坏示范）；wordmirror 经核实为"零数据出厂"设计，不在清理范围。
