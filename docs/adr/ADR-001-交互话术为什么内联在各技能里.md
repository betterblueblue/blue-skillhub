# ADR-001 交互话术为什么内联在各技能里

日期：2026-09-05　状态：已采纳

## 决定

改进记录的交互话术（"这次发现一个可能值得用于改进 Skill 的问题……要把它记录下来吗？"）必须内联在各技能 SKILL.md 里，不抽进共享文件 `skills/_common/rules.md`。涉及 intent-anchor、pathfinder、impact 三处。

## 为什么

`tests/test_skill_improvement_prompt.py` 锁定了话术必须内联——技能要**自包含**：被单独复制到其他环境、拿不到仓库共享文件时，面对用户的交互话术也必须完整可用。这是技能脱离仓库独立安装的底线。

## 代价

改话术要同步三个文件。用这个重复换取自包含，值得。

## 曾经考虑过

把话术收进 rules.md 做单源（2026-09-05 的 0.1.2 版曾这样做）——被 2 个失败的契约测试否决（intent-anchor 丢失"要把它记录下来吗？"、impact 缺失"普通完成不询问"），0.1.3 回退为内联。

## 边界

rules.md 仍然收编**语义规则**（确认语义、面向用户表述、验证声明、档位升降）；只有"面对用户的一段话术"这类必须原样出现的内容留在内联。
