# ADR-003 轻量档为什么只升不降

日期：2026-09-05　状态：已采纳

## 决定

intent-chain 的轻量档与标准档之间**只允许单向升级**（轻量 → 标准），轻量档进行中任一定档条件被破坏（需要数据库 / 权限 / 对外 API，或保留能力超过 5 项）时，必须停下升档、补齐标准档文档后再继续；不允许从标准档降回轻量。

## 为什么

轻量档省的是文档厚度和确认次数，**不省验收路径、假设表、V2 证据和校验器**。如果允许降档，一个已经长出数据库的项目可以"缩回"轻量档绕过标准档文档——链路契约会被从中间掏空。单向门的含义是：升级永远补文档，永不删保障。

## 边界

各技能自己定义升档触发条件（intent-anchor 定档四条件、intent-design 发现 DB/API/权限、intent-visual 发现完整品牌体系），本 ADR 只定"单向"方向。
