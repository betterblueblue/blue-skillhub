# Pathfinder 迭代历史

## 未发布：两段式地图（2026-11-01）

旧模板有 17 个必填节，同一件事在几节里各写一遍，每条都打标签，读起来像拼起来的。一份真实项目的地图有 357 行：启动命令写了 4 遍，同样 5 个文件和行号写了 2 遍，【已核实】打了 132 个。

- 地图改成两段：前段「导读」写给人，按七个问题排，约 100 行；后段「参考数据」带证据，按编号查，impact 照旧从【0】读。
- 旧【1】【4】【12】并进导读，旧【7】拆进【2】和【8】，旧【11】的逐跳证据并进【4A】阶段表；保留的编号不变，impact 不用改。图从四张减到两张（导读一张、【6】ER 图一张）。
- 一个事实只放一个节，别处写「见【N】」；导读只写结论，只给猜测标【推断】。
- 写作顺序倒过来：先整理参考数据，最后写导读，再统稿自查；Phase 2 子 agent 的报告只当素材，不按路照贴。
- 校验器：V12 不再要求【4A】画图；新增 V13（导读七问齐全、有运转图、改动导航至少一行，缺即 FAIL；超 150 行、贴证据 WARN）和 V14（同一条证据重复出现 WARN）。`--refresh` 下旧格式地图缺导读只报 WARN，并提示整份重跑。
- 样例地图 `tests/fixtures/degradation-trap` 按新格式重写，新校验器下 14 项全过、0 WARN；旧样例在新校验器下 V13 FAIL，V14 查出 12 条重复证据。
- 顺带补回 `phase-3-depth-fill.md` 里加【4A】时丢掉的「【6】数据模型概览」标题。

## 未发布：评审修复（2026-11-01）

- 模板补回 `## 【5】关键入口` 标题：加【4A】时误删，入口表被并进【4A】，照模板写的地图没有【5】。新增模板章节测试防止再丢。
- V7 认得文档给的跳过写法：`phase-3-depth-fill.md` 让写「【14】代码风格观察因预算耗尽未产出」，旧 V7 只认同一行里有「跳过」，照写反而 FAIL；模板列头的理由词「超预算」也加进预算耗尽关键词。理由不是预算或超大仓时仍 FAIL。
- Git 归属检查改用 `git rev-parse --show-prefix`：旧写法 `test -d .git` 在 worktree、submodule 根目录（`.git` 是文件）误判为子目录，和 `pf_git.py` 的结论相反，V9/V11 随之 FAIL。
- 改进记录默认只在对话里整理，用户明确要求保存并确认路径后才写文件。
- SKILL.md 开头补「脚本路径」：`{pathfinder skill 目录}` 就是 `${CLAUDE_SKILL_DIR}`，Claude Code 会换成实际目录，别的客户端照旧用 SKILL.md 所在目录。
- 测试修正：`test_scan_this_repo` 用的 `parents[5]` 是仓库的上一级目录，本地会扫到整个上级文件夹而超时，改为 `parents[4]`；`run.sh` 的 P3 场景（`url: local-only`）改为找随仓库提交的 `tests/fixtures/degradation-trap`，不再要求 `test-projects/` 里有一份手工副本。
