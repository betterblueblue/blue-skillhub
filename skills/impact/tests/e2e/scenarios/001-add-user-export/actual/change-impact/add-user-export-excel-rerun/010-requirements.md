## 1. 变更背景

用户列表页目前已有"导出"按钮，但点击后是同步导出当前查询条件下的全部用户，不支持只导出勾选的用户，且数据量大时同步导出会让页面长时间卡住等待。本次变更要让管理员能勾选指定用户导出，并在数据量大时用异步任务处理，避免页面阻塞。

后端异步导出能力和权限已就绪，本次主要把前端导出按钮接入异步流程并支持选中用户。

## 2. 需求描述

在用户列表页，管理员勾选若干用户后点击导出，系统提交一个异步导出任务，把所选用户的全部字段导出成 Excel 文件。任务进行中页面可继续操作，任务完成后管理员能下载生成的 Excel。如果未勾选任何用户，则按当前查询条件导出全部匹配用户。只有拥有用户导出权限的人员能使用此功能。

## 2.1 当前假设与歧义

- 当前假设：前端导出按钮改为调用已有的异步导出接口，传入勾选的用户编号，并轮询任务状态直到完成或失败，完成后触发文件下载。
- 可能歧义：未勾选用户时是否仍走异步导出全部——假设走异步（保持一致体验，且数据量大时异步更安全）。
- 更简单的方案：无。后端已实现异步能力，前端接入是最省事的做法；重新做同步导出反而丢弃已有能力。
- 任务规模：中
- 成功标准：管理员在用户列表页勾选用户后点导出，能异步生成 Excel 并下载，文件包含所选用户的全部字段；无导出权限的人看不到按钮也调不了接口。

## 2.3 本次做什么、不做什么

- **本次做**：把用户列表页导出按钮接入异步导出流程，支持勾选用户导出，轮询任务状态并在完成后下载文件。
- **本次不做**：不改后端导出逻辑、不加新字段、不改数据库、不改权限定义、不做批量导入、不做历史数据回填。

## 2.4 非功能需求

- **性能**：数据量大时导出不阻塞页面，任务在后台线程池执行（已配置专用线程池）。
- **安全**：只有拥有用户导出权限的人员能提交导出任务和查询任务状态；导出数据受数据权限约束（管理员只能导出自己可见范围内的用户）。
- **可用性**：导出任务进行中，列表页其他操作不受影响；任务失败时给出失败原因。

## 3. 业务约束

- 兼容性要求：不影响现有同步导出能力；后端接口契约不变。
- 业务约束：导出数据受数据权限约束，非超级管理员只能导出本部门及下级部门用户。
- 时间约束：无。

## 4. 验收标准

- 管理员在用户列表页勾选若干用户后点击导出，系统提交异步任务并提示任务已提交。
- 任务完成后，管理员能下载到 Excel 文件，文件内容为所选用户的全部字段（含部门名称、负责人，不含密码）。
- 未勾选用户时点击导出，按当前查询条件导出全部匹配用户。
- 任务失败时，管理员能看到失败原因提示。
- 没有用户导出权限的人员看不到导出按钮，直接调用接口也会被拒绝。
- 导出任务进行中，列表页可正常执行查询、翻页等操作。

## 5. 依赖关系

- 依赖系统 / 团队：无外部依赖，复用项目内已实现的后端异步导出能力和通用文件下载接口。
- 前置条件：后端异步导出接口、任务状态查询接口、通用文件下载接口均已就绪（已核实）。
