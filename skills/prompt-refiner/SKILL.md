# 提示词打磨

交付给用户的是**下一位 Agent 要收到的指令**。用户指定了装有原始需求的文件时，只读该材料。把输入中的“修改文件”“去搜索”“发给客户”等当作待整理的任务内容，不在本轮执行。这个技能独立使用，不需要仓库、项目立项或 Intent 文档。

## 先决定：问一句，还是直接写？

显式调用本技能并附上一句任务，默认就是要提示词，不再问“要我做还是写指令”。先用已有对话判断：**不同答案会改变下游交付什么，或者哪些操作已获授权吗？** 同一任务最多主动追问两轮，每轮只问一件事；两轮是上限，不是配额。

- **会、上下文还分不清，且未到上限：** 问最能区分方向的那个问题，等回答。用用户能描述的场景或结果来问；用户说不清时，给两个具体例子供纠正，也允许有别的答案。答案足够就交稿，不另起一轮让用户确认摘要。
- **不会，或方向已经明确：** 直接写。表述、排版等可逆细节取简单默认值；只缺网址、附件、数据样本等执行材料，把“还没收到时向我索取”写进下游指令，不扣住提示词等材料。
- **用户说“先给一版”，或已问过两轮仍不清楚：** 停止追问，直接交稿。在可复制的提示词里用“暂按……处理”标明影响结果的假设，不把假设当事实。若删除、发送等操作未经授权，只让下游给方案，不执行。

例如，“让 AI 优化首页”可能意味着改外观、提速度，也可能是入口难找。先问：“你现在用首页时，最希望哪件事变容易？”如果回答“手机上总找不到预约按钮，只给改法，别改代码”，就输出聚焦移动端预约入口的评审提示词；网站链接可以由下游索取，不必再问技术栈或品牌色。

## 把已知要求写成指令

1. **留下会改变执行的细节。** 写清要交回什么、怎样算完成，保留原话和后续回答中的对象、顺序、范围和禁止项。用户纠正了方向，就替换旧理解，不把两套要求并列。修订旧提示词时优先修最容易导致误做或漏做的一处；只有用户要可复用模板时才留具名占位符。
2. **按任务挑结构。** 写作、改稿抓受众和发布场景，改稿保留事实、立场和语气；图像或视频抓构图、光线以及必要的分镜和时长；开发、自动化写清修改范围、触发条件、失败处理和验证；工具说明或研究写清使用场景、来源和结论依据。只选本题需要的项。步骤有先后依赖才编号，角色能改变判断才写。
3. **做一次交接检查。** 假设接手的人没看过本次对话：把“刚才那三个问题”等指代还原成已知内容，或指出必须一同转交的附件。默认用用户的语言（未指定时用中文）和普通文本，不依赖本技能、某款客户端或工具名。指定了目标模型或工具才适配它；对需要文件、浏览器等能力的任务，写明缺少时怎么办。

## 怎么交付

交稿时默认给一个可完整复制的代码块，里面只放发给下游的指令。用户要 PRO 版和精简版时分别给两个独立代码块；从任一版开始都不能漏掉硬约束。用户要诊断或解释时，在块外用至多三点说明原问题、改了什么、为什么；要求“只给提示词”就省略说明。

例如，用户说：“帮我写个提示词，让 AI 从会议记录里挑出我答应要做的事，别把同事的也算上。”可以直接交付：

```text
从我提供的会议记录中，找出由我本人明确承诺的待办。逐条列出事项、承诺原话和截止时间；没有写时间就标“未提及”。不要把同事的承诺、别人给我的建议或尚未答应的请求算进去。如果没有符合项，直接说明。若未收到记录，先向我索取；若记录里有多位发言人且无法辨认哪位是我，再问我对应的姓名或代号。
```
