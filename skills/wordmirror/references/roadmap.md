# 路线图 · 管道自动化大件（都还没做）

> 这份文件记的是"已知短板、没动手"的清单。下面每一项都是**未来工作**——
> 没有任何一个已经实现。做完了从这里划掉，别把计划写成能力。

## 为什么挂起

成熟记忆项目（Mem0、Letta、Zep、claude-mem、agentmemory）的写入和投递都是自动的；
wordmirror 目前写入靠 Agent 自觉跑 `wm.py`、投递靠 skill 恰好被加载。
这两层补上之前，协议写得再好也只是纸面能力。

## 待办（按依赖排序）

### 1. 投递层：开工自动注入

新会话里 Agent 凭什么知道去读 `~/.wordmirror/`？现在唯一的路是"skill 被加载→读 SKILL.md 路由"。
目标：开工时 `current-context.md` + `habits.md`（开工必读段）自动进上下文。

- 候选路径：MCP server / 各工具的会话钩子（SessionStart 类）/ 规则文件集成。
- 约束：本地优先，不外发；注入的是文件不是数据库。
- 依赖：无，但 1 和 2 一起做才闭环（写进去了没人读=白写）。

### 2. 写入侧自动化钩子

会话结束或蒸馏时，自动把新决定/纠正种进 `user_writebacks.jsonl` / `corrections.jsonl`。
现在全靠 Agent 记得跑 `wm.py wb/corr`——真实数据里两个文件至今不存在，就是证据。

- 候选路径：会话收尾钩子跑候选提取 → Agent 确认 → `wm.py` 写入。
- 红线不变：**脚本产候选，Agent 定结论**，脚本不许自动把候选写成事实。
- 依赖：第 9 节蒸馏提示词（决定补录标准）已就位，见 `distill-prompts.md`。

### 3. 检索排序

现在是 grep + 可选向量索引，返回原始行序。目标：按相关度+时效加权返回 top-k，
带元数据（日期/来源/命中文件）。

- 约束：继续本地优先；`vecsearch.py` 已有向量底子，可在这上面加排序。
- 验收口径：问"那个项目的决定是什么"能先返回最近的决定，不是最早撞上的关键词行。

### 4. 记忆有效性评测

现有自检只查**忠实性**（引文可回查），没人量"记忆有没有让回答变对"。

- 方向：攒一组"有记忆 vs 无记忆"的对比问答（开工接话、欠账提醒、习惯命中），
  人工或脚本对比；参考 LoCoMo/LongMemEval 的思路但用我们自己的语料。
- 这是最后一项——前三项落地后才有东西可评。
