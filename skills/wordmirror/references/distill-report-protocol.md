# 报告蒸馏协议 · 判断还给 Agent，脚本只做确定性

> 触发场景：ingest 跑完、用户说"更新报告 / 重新整理 / 报告过期了"、或首次初始化。
> 原则：**这 4 份文件由你（Agent）读语料后用人话写。脚本只产候选素材，不替你下结论。**
> 脚本给的 materials_*.json / stats_*.json 是"线索"，不是"成品"——你要自己抽读语料核实、滤掉假阳性。

## 要写的 6 份文件（都写在数据目录 data/profile/ 下）

| 文件 | 对应 HTML 页 | 回答什么问题 |
|---|---|---|
| decisions.md | 02 我做过的重要决定 | 我做过哪些重要决定、后来怎样 |
| recurs.md | 05 我反复提的事 | 我反复纠结/反复问、一直没解决的事 |
| tasks.md | 07 我总让 AI 干什么 | 我总把什么活丢给 AI |
| ai-view.md | 08 AI 怎么看我 | AI 眼里我是什么样 |
| agents.md | 06 我在各 AI 里的样子（下半部分） | 每个 AI 里我主要干啥、怎么跟它说话 |
| timeline.md | 09 走过的这几个月 | 这几个月我是怎么过的、哪些转向 |

## 共同规则

1. 用 `## 小节` 分节，**不要写 `# 大标题`**（HTML 页自己会放大标题）。
2. 引用原话必须带日期（YYYY-MM-DD），从 `data/corpus_dedup.jsonl`（用户的话）或 `data/ai_messages.jsonl`（AI 的话）里**实际搜出来**的，不许凭记忆默写。
3. 每个判断都要有依据：至少一条原话 + 日期；拿不准的标"（推断）"或干脆删掉。
4. **滤假阳性**：脚本候选里混着指令文本、代码、讨论稿、客套话——这些不是你要的，读一遍挑出来丢掉。
5. 没有料就写一句"还没什么可说的"，不硬凑字数。
6. 说人话：正文不许出现"语料 / 画像 / 蒸馏 / 语义 / 向量 / 归档"这类内部词。

## 各文件怎么写

### decisions.md（重要决定）

- 候选来自 `data/materials_decisions.json`（脚本按"我决定 / 先不 / 算了 / 选 X"抓的句子），但**只留真正重要的**：改变方向、放弃一件事、拍板一个选择。指令、代码片段、随口一提都丢掉。
- 按主题分节，每条格式：日期 + 当时说的原话；如果后来有反转/结果，补一句"后来"。
- 例：
  ```markdown
  ## 求职
  - 2026-06-07「我准备还是去找工作了，在职考吧」——后来 8 月连考三次被打击到，9 月改口放弃考公
  - 2026-09-01「我决定放弃考公去找工作」
  ```

### recurs.md（反复提、没下文）

- 从语料里找**你反复提、跨了几个月、一直没下文**的事。**不要按文件夹名分组**——你要读懂后自己归纳成主题。
- **"反复"只写在这**：照见（insights.jsonl）不含"反复"，别两边都写。
- 每条：这件事是什么、最早/最近什么时候提的、大概提了几次、卡在哪。
- 例：
  ```markdown
  ## 短视频起号
  - 7 月底到 8 月底提了 4 次（3D 场景起号、音乐可视化发抖音），一直没见起号的结果
  - 2026-07-28「我想拿这个作品去短视频平台起号」
  - 2026-08-02「我产出视频的最终目的是为了发布短视频平台」
  ```

### tasks.md（总让 AI 干什么）

- 读语料，**自己归纳**你主要让 AI 干哪几类活。不是词表计数，是你看完大量原话后的判断。
- 每类给一个大致占比 + 一句人话 + 一条典型原话。**占比加起来凑成十成（100%），别超**；拿不准就写"最多 / 大概"这类模糊词。
- 例：
  ```markdown
  ## 写代码（约占四成）
  - 2026-08-12「帮我写个爬虫，抓这个页面的列表」
  ## 改文案（约占三成）
  - 2026-08-20「这段润色一下，别太硬」
  ## 做决定（容易被忽略的一类）
  - 你经常把纠结丢给 AI：「该不该接这个 offer」「要不要继续考」
  ```

### ai-view.md（AI 怎么看我）

- 从 `data/ai_messages.jsonl` 里挑 **AI 真在说你习惯 / 风格 / 偏好**的话。滤掉：技术讨论、客套（"好的"）、以及 AI 在复述你原话的。
- 按 AI 工具分节，每条带日期 + 原话。
- 例：
  ```markdown
  ## Claude Code
  - 2026-08-31「你总是先列一堆假设再动手，这次我直接按最简单的来了」
  ## zcode
  - 2026-08-30「你的问题一直很具体，但很少说自己最终要什么」
  ```

### agents.md（每个 AI 里我什么样）

- 06 页的上半部分（哪个用得最多）是脚本算的，**这页的下半部分要你写**。
- 按用量从多到少，每个 AI 一小节，写两行：**主要在干** + **怎么跟它说话**。
- "怎么跟它说话"**不许照抄脚本的数字**（中位/占比/谢谢次数这类），你要读 stats_agents.json + 抽读语料，用一句人话点出这个工具里的特征，尤其是和别的工具不一样的地方。
- 例：
  ```markdown
  ## Claude Code（5430 条）
  - 主要在干：blue-skillhub、govshield、小红书
  - 怎么说话：短句快节奏，一条指令就完事，基本不客套
  ## zcode（566 条）
  - 主要在干：jobsearch、explore
  - 怎么说话：一写就是长篇，近一半是长指令，像在写方案
  ```

### timeline.md（这几个月怎么过的）

- 从 `materials_monthly.json`（每月条数、top 主题）+ 抽读语料，写一段**按时间顺序的叙述**：这几个月你主要在忙什么、重心什么时候转了、哪个月明显变忙/变闲。
- 重点写**转向和变化**，不要只罗列每月条数；最近这个月单独写一节，当"月报"用（这一页取代脚本生成的月度报告）。
- 例：
  ```markdown
  ## 2025-11 ~ 12：备考
  - 做申论训练系统、素材 RAG，重心在考公
  ## 2026-01 ~ 03：短视频 + 事业单位
  - 同时做内容系统和四川事业单位备考 skill
  ## 2026-06 起：转求职
  - 「我准备还是去找工作了，在职考吧」，之后求职成了主线
  ## 最近这个月（2026-09）
  - 继续打磨 wordmirror，blue-skillhub 是主要战线
  ```

## 写完之后

1. 告诉用户"报告更新了"，让他看一眼有没有说错，当场改。
2. 这几份 MD 是快照，不会自动更新——你说过的话变多了、要重新整理时，重跑本协议。
3. 写坏了（格式不对）不影响别的页；重写覆盖即可。
