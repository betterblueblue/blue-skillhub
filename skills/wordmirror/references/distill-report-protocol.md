# 报告蒸馏协议 · 判断还给 Agent，脚本只做确定性

> 触发场景：ingest 跑完、用户说"更新报告 / 重新整理 / 报告过期了"、或首次初始化。
> 原则：**这 6 份文件由你（Agent）读语料后用人话写。脚本只产候选素材，不替你下结论。**
> **⚠️ 照见（insights.jsonl）是另一份活，走 `mirror-protocol.md`——"更新报告"时和这 6 份一起定稿，别只写 MD 漏了照见。**
> 脚本给的 materials_*.json / stats_*.json 是"线索"，不是"成品"——你要自己抽读语料核实、滤掉假阳性。

## 先看这个：有料还是凑数

用户看这些页，是想被**照见**——看见自己没意识到的自己。**一句总结如果他自己都能猜到，就是凑数。**

| 凑数（重写） | 有料（照这样） |
|---|---|
| 你话比较短 | 你给 AI 下指令大多 20 字以内，一句一个活，像对熟练工下工单 |
| 主要项目：blue-skillhub、小红书 | 2026-06 你说了句「我准备还是去找工作了，在职考吧」，之后求职成了主线 |
| 你爱提问 | 你会反问 AI 的推理——「为什么一直揪着相似度不放」 |
| 你说话直接 | 你会说「你他妈的不要我说什么你就附和什么啊」（2026-07-04） |

**三条硬规矩：**
1. 每个判断都要配一条**能撑起它的原话**，而且挑**最带劲的那句**，不是最普通的那句。
2. 优先写**反差和转折**（考公→求职、老板→学徒、客气→骂街），不要平铺直叙的总结。
3. 写不出原话的，宁可删掉，不许用"大概 / 可能 / 比较"糊过去。

## 要写的 6 份文件（都写在数据目录 data/profile/ 下）

| 文件 | 对应 HTML 页 | 回答什么问题 |
|---|---|---|
| decisions.md | 02 我做过的重要决定 | 我做过哪些重要决定、后来怎样 |
| recurs.md | 05 我反复提的事 | 我反复纠结/反复问、一直没解决的事 |
| tasks.md | 07 我总让 AI 干什么 | 我总把什么活丢给 AI |
| ai-view.md | 08 AI 怎么看我 | AI 眼里我是什么样 |
| agents.md | 06 我在各 AI 里的样子（下半部分） | 每个 AI 里我主要干啥、怎么跟它说话 |
| timeline.md | 09 走过的这几个月 | 这几个月我是怎么过的、哪些转向 |

**另外还有一份不是 MD 的账本要补：** `promises.jsonl`（03 页「说过要做的事」）——从语料抽读「我要做 X / 我决定 X / 我准备 X / 我打算 X」这类**明确承诺**，用 `python scripts/wm.py promise add "…"` 逐条补录（带日期）。**这是判断活，别漏，否则 03 页永远空着。**

03 页的呈现重点是“后来都去了哪里”，不是“说到做到率”：`open` 只写“还没做完”，不能擅自解释成拖延或失败；`closed` 才写“办完了”；`dropped` 才写“已经收线”。账本没有后续证据时，不要替事项编造“变成了另一件事”或“在等外部消息”。

## 共同规则

1. 用 `## 小节` 分节，**不要写 `# 大标题`**（HTML 页自己会放大标题）。
2. 引用原话必须带日期（YYYY-MM-DD），从 `data/corpus_dedup.jsonl`（用户的话）或 `data/ai_messages.jsonl`（AI 的话）里**实际搜出来**的，不许凭记忆默写。
3. 每个判断都要有依据：至少一条原话 + 日期；拿不准的标"（推断）"或干脆删掉。
4. **滤假阳性**：脚本候选里混着指令文本、代码、讨论稿、客套话——这些不是你要的，读一遍挑出来丢掉。
5. 没有料就写一句"还没什么可说的"，不硬凑字数。
6. 说人话：正文不许出现"语料 / 画像 / 蒸馏 / 语义 / 向量 / 归档"这类内部词。

## 各文件怎么写

### decisions.md（重要决定）

- 候选来自 `data/materials_decisions.json`（脚本按"我决定 / 先不 / 算了 / 选 X"抓的句子），但**只留真正重要的**：改变方向、放弃一件事、拍板一个选择。指令、代码片段、随口一提都丢掉。
- 优先把决定写成“后来去了哪里”，不要只列清单：
  - `## 这句话后来去了哪里`：第一条用 `「用户原话」（YYYY-MM-DD）`，后续用 `- YYYY-MM-DD 事实`，只写实际发生的后续。
  - `## 隔了几个月，还是这件事`：至少两条跨时间原话，说明持续存在的选择原则。
  - `## 这个决定还没有答案`：已经说出口但结果未明的决定，原话后留开放问题，不替用户判断。
  - 只有找到真实的前后两条原话时，才使用 `## 以前的想法，后来的选择`；没有证据不要硬凑对照。
- 普通主题章节仍可使用。每个判断都要有日期原话；如果后来有反转/结果，补带日期的事实。
- 例：
  ```markdown
  ## 求职
  - 2026-06-07「我准备还是去找工作了，在职考吧」——后来 8 月连考三次被打击到，9 月改口放弃考公
  - 2026-09-01「我决定放弃考公去找工作」
  ```

### recurs.md（反复提、没下文）

- 从语料里找**你反复提、跨了几个月、一直没下文**的事。**不要按文件夹名分组**——你要读懂后自己归纳成主题。
- 优先用白话栏目组织：`这几句话，原来在问同一件事`（跨时间原话相遇）、`一直回来找答案`（同一问题在不同阶段出现）、`还没有走完的一条线`（没有明确完成或放弃的主题）、`这条线后来转去了别处`（有事实支撑的方向转移）。
- **"反复"只写在这**：照见（insights.jsonl）不含"反复"，别两边都写。
- 每条至少有两条带日期的真实原话和一段克制的承接；不能只靠关键词计数，不能把反复写成拖延、性格或心理诊断。
- “没再提”不等于放弃；没有真正联系的素材删掉，不要为了填栏目硬凑。
- 例：
  ```markdown
  ## 短视频起号
  - 7 月底到 8 月底提了 4 次（3D 场景起号、音乐可视化发抖音），一直没见起号的结果
  - 2026-07-28「我想拿这个作品去短视频平台起号」
  - 2026-08-02「我产出视频的最终目的是为了发布短视频平台」
  ```

### tasks.md（总让 AI 干什么）

- 读语料，**自己归纳**你主要让 AI 干哪几类活。不是词表计数，是你看完大量原话后的判断。
- 优先用“我把什么交给 AI”“让 AI 去查证和巡检”“我自己还是抓着问题的主人”等人话标题；每类写具体工作和一条带日期的代表原话。
- 数字比例只能作背景，不能取代原话和具体语境；不要把“交给 AI”写成用户放弃判断。
- 例：
  ```markdown
  ## 写代码（约占四成）
  - 2026-08-12「帮我写个爬虫，抓这个页面的列表」
  ## 改文案（约占三成）
  - 2026-08-20「这段润色一下，别太硬」
  ## 做决定（容易被忽略的一类）
  - 你经常把纠结丢给 AI：「该不该接这个 offer」「要不要继续考」
  ```

### ai-view.md（AI 怎么看我）

- 从 `data/ai_messages.jsonl` 里挑 **AI 真在说你习惯 / 风格 / 偏好**的话。滤掉：技术讨论、客套（"好的"）、以及 AI 在复述你原话的。
- 优先用白话栏目组织，而不是只按工具分节：`不同 AI 都看见了这一点`（至少两条独立观察指向同一现象）、`AI 这样看我`（具体、有证据的单条观察）、`AI 也看错过我`（必须同时有 AI 原话和用户纠正/后续事实）、`现在，AI 应该这样认识我`（把已反复验证的协作认识写给未来的 AI）。
- 每条 AI 引文必须带日期和工具来源；AI 的描述是观察材料，不是人格诊断或事实定论。没有真实纠正证据时不要硬写“看错过”。
- 按 AI 工具分节的旧格式仍可兼容，每条带日期 + 原话。
- 例：
  ```markdown
  ## Claude Code
  - 2026-08-31「你总是先列一堆假设再动手，这次我直接按最简单的来了」
  ## zcode
  - 2026-08-30「你的问题一直很具体，但很少说自己最终要什么」
  ```

### agents.md（每个 AI 里我什么样）

- 06 页的上半部分（哪个用得最多）是脚本算的，**这页的下半部分要你写**。
- 可以用白话栏目组织：`在这里，我是什么样`（各 AI 的场景卡）、`换了 AI，我也换了一种说法`（不同工具原话对照）、`哪些东西一直跟着我`（跨工具共同要求）、`现在回头看`（克制收尾）。
- 按用量从多到少，每个 AI 一小节，写：**主要在干** + **怎么跟它说话** + 一条真实代表原话（日期和工具）。
- "怎么跟它说话"**不许照抄脚本的数字**（中位/占比/谢谢次数这类），你要读 stats_agents.json + 抽读语料，用一句人话点出这个工具里的特征，尤其是和别的工具不一样的地方。
- 跨 AI 对照必须有独立来源的原话；没有证据不评价哪个 AI 更懂用户。AI 的观察不是人格诊断，也不是确定事实。
- 例：
  ```markdown
  ## Claude Code（5430 条）
  - 主要在干：blue-skillhub、govshield、小红书
  - 怎么说话：短句快节奏，一条指令就完事，基本不客套
  ## zcode（566 条）
  - 主要在干：jobsearch、explore
  - 怎么说话：一写就是长篇，近一半是长指令，像在写方案
  ```

### timeline.md（这几个月怎么过的）

- 从 `materials_monthly.json`（每月条数、top 主题）+ 抽读语料，写一段**按时间顺序的叙述**：这几个月你主要在忙什么、重心什么时候转了、哪个月明显变忙/变闲。
- 重点写**转向和变化**，不要只罗列每月条数；阶段标题要用人话，不要只写项目名。
- 阶段叙述之后，可以按实际证据补充这些白话回望段，让不同时间的原话相遇：
  - `## 以前的我，后来的我`：两条不同时间的原话，分别说明前后变化。
  - `## 这句话后来去了哪里`：第一条是关键原话，后面用 `- YYYY-MM-DD 事件` 写它之后发生的事实。
  - `## 隔了几个月，还是这件事`：多条跨时间原话，说明持续出现的关注，不写成简单词频。
  - `## 原来这两句话有关`：两条看似分散但确有联系的原话，说明为什么放在一起。
  - `## 这件事后来怎么样了`：被放下但没有明确结束的事情，只写事实，最后可留开放问题。
  - `## 现在的我，停在这里`：最近状态和一两条当前原话，作为这一页的收尾。
- 引文格式必须是 `「用户原话」（YYYY-MM-DD）`，从 `corpus_dedup.jsonl` 实际检索后复制；不要凭记忆改写。没有足够有力的原话就删掉这一段，不要凑数。
- 最近这个月单独写一节，当"月报"用（这一页取代脚本生成的月度报告）。
- 例：
  ```markdown
  ## 2025-11 ~ 12：备考
  - 做申论训练系统、素材 RAG，重心在考公
  ## 2026-01 ~ 03：短视频 + 事业单位
  - 同时做内容系统和四川事业单位备考 skill
  ## 2026-06 起：转求职
  - 「我准备还是去找工作了，在职考吧」，之后求职成了主线
  ## 最近这个月（2026-09）
  - 继续打磨 wordmirror，blue-skillhub 是主要战线
  ```

## 写完之后

1. 跑 `python scripts/render.py all` 刷新 HTML——**脚本只排版，写完 MD 不重跑，页面不会自己变**。
2. 告诉用户"报告更新了"，让他看一眼有没有说错，当场改。
3. 这几份 MD 是快照，不会自动更新——你说过的话变多了、要重新整理时，重跑本协议。
4. 写坏了（格式不对）不影响别的页；重写覆盖即可。
