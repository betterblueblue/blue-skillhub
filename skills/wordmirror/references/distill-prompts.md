# WordMirror Agent 蒸馏提示词总表

> 本文件是 Agent 蒸馏的**执行入口**：需要整理任何一个产物时，先读这里对应的提示词，再按需读相关协议细化。
> 每个产物都用同一套八字段结构：**任务目标 / 输入文件 / 允许的证据 / 输出文件 / 章节结构 / 引用规则 / 禁止事项 / 验收标准**。
> 本表是现有协议（`distill-report-protocol.md`、`mirror-protocol.md`、`portrait-template.md`、`habits-template.md`、`init-protocol.md`、`writeback-protocol.md`）的执行层浓缩，不与之冲突。

# 第一部分 · 总编排提示词（读任何 MD 前先建立判断）

```text
你不是在生成一份统计报告，而是在做「以言为镜」。

把用户说给 AI 的话重新放回时间和关系里，让用户看见：
- 自己以前没注意到的变化
- 不同时间反复出现的要求
- 一句话后来带来的变化
- 两句话之间原来存在的联系
- 曾经认真想过、后来被放下的事情
- 不同 AI 眼中的不同侧面

原话是内容主角，数字只是背景。
每个判断必须有真实原话和日期作为依据；没有证据就删，不凑内容。
不要替用户做心理诊断、性格判断或动机推断。
```

**职责分工**

```text
脚本负责：探测存档、提取消息、去重、统计、产候选、渲染 HTML。
Agent 负责：读原话、筛选候选、判断哪些内容有价值、归并跨时间/项目关系、写成人话、更新各页 MD、定稿 promises 和 insights。
```

**通用禁止（任何时候）**

```text
不要直接把 materials_*.json 当报告。
不要直接把 stats_*.json 当结论。
不要把关键词命中当作用户习惯。
不要把「没再提」直接判定为放弃。
不要把「我想做」全部当作明确承诺。
不要把 AI 的夸奖直接当作用户事实。
不要用用户不会说的抽象词、发明术语。
不要把报告整理成“开始—成长—成功”的鸡汤。
```

**数据源 ↔ 产物对照**

| 输入 | 用途 | 主要产物 |
|---|---|---|
| `corpus_dedup.jsonl` 用户原话 | 行为、决定、转折、承诺、口头禅证据 | portrait / habits / decisions / recurs / tasks / timeline / promises / insights |
| `ai_messages.jsonl` AI 原话 | AI 对用户的观察 | ai-view / agents |
| `stats_wordfreq.json` 词频 | 高频词（通用词表计数，非口头禅） | habits 词表 |
| `stats_agents.json` 分工具 | 各 AI 用量、top 项目 | agents / habits 的 AI 表 |
| `materials_decisions/insights/monthly/projects.json` 候选人 | 只当线索，不直接上页，需 Agent 回查核实 | decisions / insights / timeline / recurs |

**有料还是凑数（贯穿所有产物）**

```text
一句总结如果用户自己能猜到，就是凑数。
马上会出现的好内容：具体的原话 + 时间/关系 + 让他自己联系起来的承接。
凑数往往是：平淡的性格描述、项目目录流水账、没有证据的方向总结。
```

# 第二部分 · 每个产物的专用提示词

## 1. portrait.md（我是谁）

- **任务目标**：写一份“我是谁、怎么跟我说”的说明书，让新会话一眼知道你；不只堆简历，重点是让人看见转折和没串起来的地方。
- **输入文件**：`corpus_dedup.jsonl`、`stats_wordfreq.json`、`materials_monthly.json`、`materials_decisions.json`（后两者只当线索）。
- **允许的证据**：你的原话 + 日期；无证据的直觉判断须标“（推断）”。
- **输出文件**：`data/profile/portrait.md`。
- **章节结构**：一句话 → 基本情况 → 这 N 个月我在忙什么 → 我干活的脾气（条条有原话）→ 我自己都没想明白的地方 → 版本修正记录。
- **引用规则**：原话带日期；写不出日期的删掉。
- **禁止事项**：一句话不能是“30 岁男程序员”这种谁都能套的；不评定性格；不把目录名当主题。
- **验收标准**：每个判断能找到原话+日期；重点写转折；没有凑数的空话。详情见 `portrait-template.md`。

## 2. habits.md（跟我干活的规矩）

- **任务目标**：给未来 AI 一份“怎么跟你配合”的说明，重点写“别怎么做”。
- **输入文件**：`corpus_dedup.jsonl`（教 AI 干活的原话）、`stats_wordfreq.json`、`stats_agents.json`。
- **允许的证据**：你的原话；词频必须抄脚本统计，禁止目测。
- **输出文件**：`data/profile/habits.md`。
- **章节结构**：怎么跟我说话 → 我常说的词（词｜次数｜信号意思）→ 我在不同 AI 里的样子 → 跟我搭伙的节奏 → 家里的事（如有）。
- **引用规则**：每条规则配一条原话；词表次数来自 stats。
- **禁止事项**：别写“用户喜欢清晰”这种空话；别把高频词全当口头禅；别堆中位/占比数字。
- **验收标准**：未来 AI 一看就知道该怎么做、什么不能做。详情见 `habits-template.md`。

## 3. decisions.md（重要决定）

- **任务目标**：回答“那些决定后来把你带到了哪里”，不是罗列所有包含“决定/选择”的句子。
- **输入文件**：`materials_decisions.json` + `corpus_dedup.jsonl`。
- **允许的证据**：你的原话 + 日期 + 后续事实。
- **输出文件**：`data/profile/decisions.md`。
- **章节结构**：优先用白话栏目——`这句话后来去了哪里`、`隔了几个月，还是这件事`、`这个决定还没有答案`；只有找到真实前后两条原话才用 `以前的想法，后来的选择`。
- **引用规则**：决定原话带日期；后续用带日期的事实。
- **禁止事项**：指令、代码片段、随口一提；无证据硬凑前后对照。
- **验收标准**：只留改变方向/放弃/拍板；每条能回查原话。详情见 `distill-report-protocol.md`。

## 4. recurs.md（反复提的事）

- **任务目标**：回答“你是不是一直在问同一个问题”，让不同时间的原话相遇。
- **输入文件**：`corpus_dedup.jsonl`、`materials_monthly.json`（线索）。
- **允许的证据**：跨时间、跨项目的真实原话。
- **输出文件**：`data/profile/recurs.md`。
- **章节结构**：`这几句话，原来在问同一件事`、`一直回来找答案`、`还没有走完的一条线`、`这条线后来转去了别处`。
- **引用规则**：每个主题至少两条带日期原话 + 一段克制承接。
- **禁止事项**：把关键词重复当问题重复；把反复写成拖延/完美主义/焦虑；用文件夹名代替主题理解。
- **验收标准**：不同时间的话真的在问同一件事；不制造恶评。详情见 `distill-report-protocol.md`。

## 5. tasks.md（总让 AI 干什么）

- **任务目标**：回答“你把什么活交给 AI，自己还抓着什么”，不是任务占比表。
- **输入文件**：`corpus_dedup.jsonl`。
- **允许的证据**：你的原话 + 日期。
- **输出文件**：`data/profile/tasks.md`。
- **章节结构**：`我把直接执行的活交给 AI`、`让 AI 去查证和巡检`、`为下一次面试做准备`、`让 AI 先想清楚再动手`、`我自己还是抓着问题的主人`。
- **引用规则**：每类一条真实原话 + 日期；占比只能作背景。
- **禁止事项**：不能堆“写代码四成、文案两成”；不能把交给 AI 的活写成你放弃了判断。
- **验收标准**：看得出你把执行交给 AI、把方向留给自己。详情见 `distill-report-protocol.md`。

## 6. ai-view.md（AI 怎么看你）

- **任务目标**：回答“不同 AI 是怎样认识你的”，把 AI 对你的描述变成可对照的观察。
- **输入文件**：`ai_messages.jsonl`。
- **允许的证据**：AI 真实原话 + 日期 + 工具来源。
- **输出文件**：`data/profile/ai-view.md`。
- **章节结构**：`不同 AI 都看见了这一点`（≥2 条独立观察）、`AI 这样看你`、`AI 也看错过你`（必须有纠正证据）、`现在，AI 应该这样认识你`。
- **引用规则**：每条 AI 引文带日期和工具；必须是 AI 描述用户习惯/风格/偏好的话。
- **禁止事项**：客套、技术讨论、AI 复述你原话、无依据夸奖、把 AI 观察当确定事实。
- **验收标准**：保留具体、有证据的观察；不擅自下结论。详情见 `distill-report-protocol.md`。

## 7. agents.md（各 AI 里的样子）

- **任务目标**：回答“换了工具，你是不是换了说法”，展示同一人不同场景的侧面。
- **输入文件**：`stats_agents.json` + `ai_messages.jsonl` + `agents.md` 旧版。
- **允许的证据**：你的原话 + 日期 + 工具、AI 的观察。
- **输出文件**：`data/profile/agents.md`。
- **章节结构**：`在这里，你是什么样`（每 AI 一张场景卡）、`换了 AI，你也换了一种说法`、`哪些东西一直跟着你`、`现在回头看`。
- **引用规则**：每 AI 至少一条真实代表原话；跨 AI 对照用独立来源。
- **禁止事项**：堆统计数字；根据使用量判断哪个 AI 最懂你；把用量排行当页面主体。
- **验收标准**：看得出不同工具里你不同的说话方式和承接的事。详情见 `distill-report-protocol.md`。

## 8. timeline.md（走过的这几个月）

- **任务目标**：回答“这几个月你是怎么走过来的”，按时间顺序写出转向和变化。
- **输入文件**：`materials_monthly.json`、`corpus_dedup.jsonl`。
- **允许的证据**：你的原话 + 日期。
- **输出文件**：`data/profile/timeline.md`。
- **章节结构**：按时间阶段的叙述 + 白话栏目——`以前的你，后来的你`、`这句话后来去了哪里`（配 `- YYYY-MM-DD 事实`）、`隔了几个月，还是这件事`、`原来这两句话有关`、`这件事后来怎么样了`、`现在的你，停在这里`。
- **引用规则**：阶段标题用人话；引文格式 `「原话」（YYYY-MM-DD）`，从语料检索后复制。
- **禁止事项**：罗列每月条数；长表格堆数字；把未完成的事写成结束。
- **验收标准**：重点写转向和变化；最近这月单独当“月报”用。详情见 `distill-report-protocol.md`。

## 9. promises.jsonl（说过要做的事）

- **任务目标**：回答“这些事后来各自怎么样了”，登记用户明确说过要做的事，不制造噪音清单。
- **输入文件**：`corpus_dedup.jsonl`、`materials_decisions.json`。
- **允许的证据**：用户明确说“我要做/我准备做/我打算做/我决定去做”的原话。
- **输出文件**：`data/promises.jsonl`（全局）/ 当前目录 `.wordmirror/promises.jsonl`（项目层）。
- **写入方式**：**只走命令，不手写 JSONL**：
  ```bash
  python scripts/wm.py promise add "事项" --date 原始日期 --proj 项目 --ref 原话 [--agent 工具名]
  python scripts/wm.py promise revise 关键词 --date 原始日期 [--proj 项目]
  ```
- **章节结构**（渲染层）：还没做完 / 办完了 / 已经收线（按 status=open/closed/dropped）。
- **引用规则**：补录历史承诺必须带 `--date` 原始日期（回查原话，不是登记当天）；保留 `--proj` 和 `--ref` 原话依据。
- **禁止事项**：把“我在想要不要”、技术执行指令、示例文本、讨论假设、AI 生成模板句当承诺；用登记日期冒充历史日期。
- **验收标准**：每一条能回查你什么时候说的、原话是什么；宁可少补，不塞噪音。详情见 `writeback-protocol.md`。

## 10. insights.jsonl（照见）

- **任务目标**：从候选和完整语料中筛出真正值得提醒的“事实落差”，让人停下来想。
- **输入文件**：`materials_insights.json` + `corpus_dedup.jsonl` 回查。
- **允许的证据**：真实原话 + 日期；`fact` 里必须含用户原话。
- **输出文件**：`data/profile/insights.jsonl`。
- **三类**：`say_do`（说了没做）/ `flip`（前后说法相反）/ `word_drift`（词频或表达漂移）。
- **每行格式**：
  ```json
  {"id":"gap-YYYYMMDD-N","type":"say_do","fact":"…问句…","evidence":[{"date":"…","msg":"…"}],"confidence":"high|mid","first_said":"…","last_said":"…","status":"active","user_reply":""}
  ```
- **写法规则**：`fact` 必须带原话和日期；用问句收尾、给台阶；结论权归用户；脚本候选是假阳性就丢，Agent 也可从语料自己发现。
- **禁止事项**：把“你 X 月说过 Y 之后没提”这种万能句式当照见；说破动机、性格、情绪、心理（你在逃避/你焦虑/你不成熟）；把没再提当放弃。
- **验收标准**：冲击力来自原话本身；事实带日期，用户能当场反查；不加定性判断。详情见 `mirror-protocol.md`。

# 第三部分 · 初始化交接检查表

从 `references/init-protocol.md` 抽出，用于确认初始化不是“只提取 + 只生成空态 HTML”就完成。

```text
□ portrait.md 是否已由 Agent 读原话定稿？
□ habits.md 是否已由 Agent 读原话定稿？
□ 6 份报告 MD（decisions/recurs/tasks/ai-view/agents/timeline）是否已定稿？
□ promises：是否已从历史判断并补录？为空是否说明了原因？
□ insights：是否已从候选筛选并定稿？为空是否说明了原因？
□ 是否在所有最终内容定稿后才运行 python scripts/render.py all？
□ 是否运行 python scripts/self_check.py 并确认无新增失败？
□ 03 是否有承诺数据、04 是否有照见数据，或是否已向用户说明空态的真实原因？
□ 是否已把产物文件和 03/04 状态告诉用户？
```

只要有一个 □ 未勾，初始化就不算完成，不能向用户宣布“已完成”。
