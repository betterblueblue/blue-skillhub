# WordMirror Agent 蒸馏提示词总表

> 本文件是 Agent 蒸馏的**执行入口**：需要整理任何一个产物时，先读这里对应的提示词，再按需读相关协议细化。
> 每个产物都用同一套八字段结构：**任务目标 / 输入文件 / 允许的证据 / 输出文件 / 章节结构 / 引用规则 / 禁止事项 / 验收标准**。
> 本表是现有协议（`distill-report-protocol.md`、`mirror-protocol.md`、`portrait-template.md`、`habits-template.md`、`init-protocol.md`、`writeback-protocol.md`）的执行层浓缩，不与之冲突。

# 第一部分 · 总编排提示词（读任何 MD 前先建立判断）

```text
你不是在生成一份统计报告，而是在做「以言为镜」。

把用户说给 AI 的话重新放回时间和关系里，让用户看见：
- 自己以前没注意到的变化
- 不同时间反复出现的要求
- 一句话后来带来的变化
- 两句话之间原来存在的联系
- 曾经认真想过、后来被放下的事情
- 不同 AI 眼中的不同侧面

原话是内容主角，数字只是背景。
每个判断必须有真实原话和日期作为依据；没有证据就删，不凑内容。
不要替用户做心理诊断、性格判断或动机推断。
```

**职责分工**

```text
脚本负责：探测存档、提取消息、去重、统计、产候选、渲染 HTML。
Agent 负责：读原话、筛选候选、判断哪些内容有价值、归并跨时间/项目关系、写成人话、更新各页 MD、定稿 promises 和 insights。
```

**通用禁止（任何时候）**

```text
不要直接把 materials_*.json 当报告。
不要直接把 stats_*.json 当结论。
不要把关键词命中当作用户习惯。
不要把「没再提」直接判定为放弃。
不要把「我想做」全部当作明确承诺。
不要把 AI 的夸奖直接当作用户事实。
不要用用户不会说的抽象词、发明术语。
不要把报告整理成“开始—成长—成功”的鸡汤。
```

**数据源 ↔ 产物对照**

| 输入 | 用途 | 主要产物 |
|---|---|---|
| `corpus_dedup.jsonl` 用户原话 | 行为、决定、转折、承诺、口头禅证据 | portrait / habits / lines / noticed / timeline / promises / insights |
| `ai_messages.jsonl` AI 原话 | AI 对用户的观察 | ai-eyes |
| `stats_wordfreq.json` 词频 | 高频词（通用词表计数，非口头禅） | habits 词表 |
| `stats_agents.json` 分工具 | 各 AI 用量、top 项目 | ai-eyes / habits 的 AI 表 |
| `materials_decisions/insights/monthly/projects.json` 候选人 | 只当线索，不直接上页，需 Agent 回查核实 | lines / noticed / insights / timeline |

**有料还是凑数（贯穿所有产物）**

```text
一句总结如果用户自己能猜到，就是凑数。
马上会出现的好内容：具体的原话 + 时间/关系 + 让他自己联系起来的承接。
凑数往往是：平淡的性格描述、项目目录流水账、没有证据的方向总结。
```

# 第二部分 · 每个产物的专用提示词

## 1. portrait.md（我是谁）

- **任务目标**：写一份“我是谁、怎么跟我说”的说明书，让新会话一眼知道你；不只堆简历，重点是让人看见转折和没串起来的地方。
- **输入文件**：`corpus_dedup.jsonl`、`stats_wordfreq.json`、`materials_monthly.json`、`materials_decisions.json`（后两者只当线索）。
- **允许的证据**：你的原话 + 日期；无证据的直觉判断须标“（推断）”。
- **输出文件**：`data/profile/portrait.md`。
- **章节结构**：一句话 → 基本情况 → 这 N 个月我在忙什么 → 我干活的脾气（条条有原话）→ 我自己都没想明白的地方 → 版本修正记录。
- **引用规则**：原话带日期；写不出日期的删掉。
- **禁止事项**：一句话不能是“30 岁男程序员”这种谁都能套的；不评定性格；不把目录名当主题。
- **验收标准**：每个判断能找到原话+日期；重点写转折；没有凑数的空话。详情见 `portrait-template.md`。

## 2. habits.md（跟我干活的规矩）

- **任务目标**：给未来 AI 一份“怎么跟你配合”的说明，重点写“别怎么做”。
- **输入文件**：`corpus_dedup.jsonl`（教 AI 干活的原话）、`stats_wordfreq.json`、`stats_agents.json`。
- **允许的证据**：你的原话；词频必须抄脚本统计，禁止目测。
- **输出文件**：`data/profile/habits.md`。
- **章节结构**：怎么跟我说话 → 我常说的词（词｜次数｜信号意思）→ 我在不同 AI 里的样子 → 跟我搭伙的节奏 → 家里的事（如有）。
- **引用规则**：每条规则配一条原话；词表次数来自 stats。
- **禁止事项**：别写“用户喜欢清晰”这种空话；别把高频词全当口头禅；别堆中位/占比数字。
- **验收标准**：未来 AI 一看就知道该怎么做、什么不能做。详情见 `habits-template.md`。

## 3. lines.md（02 那几条线）

- **任务目标**：把用户手上的事一条线一节摆开——怎么起的、哪里拐的、现在停在哪；不是项目清单，是每条线走到哪了的判断。
- **输入文件**：`corpus_dedup.jsonl`、`materials_monthly.json`（线索）、旧版 decisions/recurs/timeline（-历史，参考用）。
- **允许的证据**：起点原话 + 日期 + 带日期的后续事实。
- **输出文件**：`data/profile/lines.md`。
- **章节结构**：一条线一节，节标题带状态，状态只有三种——`还在走` / `已经收线` / `没了下文`。四到六条为宜，凑不满就少写。
- **引用规则**：每节至少一条起点原话（带日期）；后续用 `- YYYY-MM-DD 事实` 行。
- **禁止事项**：把文件夹名当线；把"没了下文"写成放弃或拖延；一个判断没有原话支撑。
- **验收标准**：每条线的状态都站得住（有据可查）；承接克制，不解释原因。详情见 `distill-report-protocol.md`。

## 4. noticed.md（04 你没看见的）

- **任务目标**：硬指标落点——每期至少 1 条"用户读完才知道的事"，他确认才算数；连续两期产不出就修方法，不凑数。
- **输入文件**：最近一期的 `corpus_dedup.jsonl` / `ai_messages.jsonl`（机器候选 `materials_insights.json` 只是线索，大概率假阳性）。
- **允许的证据**：带日期、能当场反查的原话；三个方向——说了没做 / 前后说法相反 / 习惯突变。
- **输出文件**：`data/profile/noticed.md`。
- **章节结构**：每期一节（标题带期间），每条发现 = 白话点题 + 原话证据 + 克制承接；用户已确认的标注"你已看过、默认成立"；末尾可带"复核记录"（哪条旧账因过时下架）。
- **引用规则**：证据必须是从原话里实际搜出来的，禁止凭记忆默写。
- **禁止事项**：拿统计维度当发现；写"你话比较短"这类用户自己都知道的话；没有发现硬凑。
- **验收标准**：用户念完愿意停下来想一会儿；这期没有就诚实写"这期没有"。详情见 `distill-report-protocol.md`。

## 5. ai-eyes.md（05 AI 眼里的你）

- **任务目标**：一页合并两件事——你在各工具里的样子 + 各 AI 对你的观察。
- **输入文件**：`stats_agents.json`（只作背景）、`ai_messages.jsonl`、`corpus_dedup.jsonl`、旧版 agents/ai-view（-历史，参考用）。
- **允许的证据**：你的原话 + 日期 + 工具；AI 描述用户习惯/风格的原话 + 日期 + 工具。
- **输出文件**：`data/profile/ai-eyes.md`。
- **章节结构**：`在这里，你是什么样`（每个常用工具一张卡：`### 工具名：一句人话` + 主要在干 + 怎么说话 + 一条代表原话）→ `换了 AI，你也换了一种说法` → `不同 AI 都看见了这一点`（≥2 条独立观察）→ `AI 这样看你` → `AI 也看错过你`（必须有纠正证据）→ `现在，AI 应该这样认识你`。
- **引用规则**：每张卡一条真实代表原话；AI 引文带日期和工具。
- **禁止事项**：堆统计数字；说哪个 AI 最懂你；把 AI 观察当人格诊断或确定事实。
- **验收标准**：既看出不同工具里的不同侧面，也看出 AI 对你认识的局限。详情见 `distill-report-protocol.md`。

## 6. timeline.md（06 这几个月）

- **任务目标**：页首回答"这个月跟上个月比变了什么"，往回回答"这一路是怎么走过来的"。
- **输入文件**：`materials_monthly.json`、`corpus_dedup.jsonl`。
- **允许的证据**：你的原话 + 日期。
- **输出文件**：`data/profile/timeline.md`。
- **章节结构**：页首 `本期对账`（新开的动作 / 变化 / 还悬着的事 / 新出现的习惯 / 教训，五行以内、每行有据）→ 按时间阶段的叙述（重点写转向和变化）→ 白话栏目——`以前的你，后来的你`、`这句话后来去了哪里`、`隔了几个月，还是这件事`、`原来这两句话有关`、`现在你停在这里`。
- **引用规则**：阶段标题用人话；用户引文统一用 `「原话」（YYYY-MM-DD）`，从语料检索后复制；只有后续节点才使用无引号的 `- YYYY-MM-DD 事实`。
- **禁止事项**：罗列每月条数；长表格堆数字；把未完成的事写成结束。
- **验收标准**：对账五行让人一眼看见变化；阶段叙述有转向。详情见 `distill-report-protocol.md`。

## 7. promises.jsonl（说过要做的事）

- **任务目标**：回答“这些事后来各自怎么样了”，登记用户明确说过要做的事，不制造噪音清单。
- **输入文件**：`corpus_dedup.jsonl`、`materials_decisions.json`。
- **允许的证据**：用户明确说“我要做/我准备做/我打算做/我决定去做”的原话。
- **输出文件**：由 `wm.py` 按运行目录自动决定——在数据根目录运行写全局 `data/promises.jsonl`，否则写当前目录 `.wordmirror/promises.jsonl`（项目层）。**渲染 03 时两层都会扫，但记账时落在哪层取决于你从哪个目录执行命令**；补录前先确认工作目录，避免账本落到错误的项目层。
- **写入方式**：**只走命令，不手写 JSONL**：
  ```bash
  python scripts/wm.py promise add "事项" --date 原始日期 --proj 项目 --ref 原话 [--agent 工具名]
  python scripts/wm.py promise revise 关键词 [--date 原始日期] [--proj 项目] [--ref 原话]
  ```
- **章节结构**（渲染层）：还没做完 / 办完了 / 已经收线（按 status=open/closed/dropped）。
- **引用规则**：补录历史承诺必须带 `--date` 原始日期（回查原话，不是登记当天）；保留 `--proj` 和 `--ref` 原话依据。已登记项缺 `--ref` 时用 `promise revise 关键词 --ref 原话` 补正。
- **禁止事项**：把“我在想要不要”、技术执行指令、普通执行指令、示例文本、讨论中的假设、AI 生成模板句当承诺；用登记日期冒充历史日期。排除词表以 `writeback-protocol.md` 为准，本文件和 init-protocol 与其一致。
- **验收标准**：每一条能回查你什么时候说的、原话是什么；宁可少补，不塞噪音。详情见 `writeback-protocol.md`。

## 8. insights.jsonl（照见）

- **任务目标**：从候选和完整语料中筛出真正值得提醒的“事实落差”，让人停下来想；每次更新复核旧账，过时的归档。
- **输入文件**：`materials_insights.json` + `corpus_dedup.jsonl` 回查。
- **允许的证据**：真实原话 + 日期；`fact` 里必须含用户原话。
- **输出文件**：`data/profile/insights.jsonl`。
- **三类**：`say_do`（说了没做）/ `flip`（前后说法相反）/ `word_drift`（词频或表达漂移）。
- **每行格式**：
  ```json
  {"id":"gap-YYYYMMDD-N","type":"say_do","fact":"…问句…","evidence":[{"date":"…","msg":"…","src":"corpus|ai_messages"}],"confidence":"high|mid","first_said":"…","last_said":"…","status":"active|confirmed|dismissed|archived","user_reply":""}
  ```
- **字段含义**：`evidence[].src` 记录证据来源（corpus 或 ai_messages）；`status` 四态——`active`（待点破）/ `confirmed`（用户认了）/ `dismissed`（用户否了并记 `user_reply`，之后不再点）/ `archived`（复核后落差不再成立，写明依据）。
- **confidence 门控**：只有 `high` 才在开工自动点破；`mid` 只在月底月初或用户问起时点。AI 定稿时核对证据属实，可把 mid 升级为 high。
- **写法规则**：`fact` 必须带原话和日期；用问句收尾、给台阶；结论权归用户；脚本候选是假阳性就丢，Agent 也可从语料自己发现；**每次更新数据时复核一遍挂着的条目，不成立的归档**。
- **禁止事项**：把“你 X 月说过 Y 之后没提”这种万能句式当照见；说破动机、性格、情绪、心理（你在逃避/你焦虑/你不成熟）；把没再提当放弃；让过时的落差留在页上。
- **验收标准**：冲击力来自原话本身；事实带日期，用户能当场反查；不加定性判断。详情见 `mirror-protocol.md`。

# 第三部分 · 初始化交接检查表

本检查表是 `references/init-protocol.md` 的执行层镜像；**判完成以 init-protocol.md 为准**，若它更新了步骤，这里要同步，不要只勾这份表就宣布完成。

03 / 04 指渲染产出的页面：**03 = 说话算数**（读 promises.jsonl），**04 = 你没看见的**（读 noticed.md + insights.jsonl）。

```text
□ portrait.md 是否已由 Agent 读原话定稿？
□ habits.md 是否已由 Agent 读原话定稿？
□ 四页报告 MD（lines/noticed/ai-eyes/timeline）是否已定稿？
□ promises：是否已从历史判断并补录？为空是否说明了原因？
□ insights：是否已从候选筛选并定稿、挂着的旧账是否复核过？为空是否说明了原因？
□ noticed.md 是否至少有 1 条"你读完才知道的事"，并已念给用户确认？没有时是否诚实写了"这期没有"？
□ 是否在所有最终内容定稿后才运行 python scripts/render.py all？
□ 是否运行 python scripts/self_check.py 并确认无新增失败？
□ 03（说话算数）是否有承诺数据、04（你没看见的）是否有内容，或是否已向用户说明空态的真实原因？
□ 是否已把产物文件和 03/04 状态告诉用户？
```

只要有一个 □ 未勾，初始化就不算完成，不能向用户宣布“已完成”。
