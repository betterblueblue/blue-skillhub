# 言镜（WordMirror）设计宪法

> 本文件回答一个问题：这个项目对外发布时，什么绝对不能变。
> 任何后续设计/代码/文档与本文冲突时，本文优先。改动本文需要用户明确同意。

## 第一条 · 每人自己跑自己的（最高原则）

- **没有服务器、没有账号、没有云端、没有遥测。** 项目方（哪怕就是作者一个人）不存在能看到用户数据的角色
- 所有数据（原话、画像、产物）只存在用户自己机器的一个目录里（默认 `~/.wordmirror/`）
- 官方发布的只有**代码和模板**——管道是公共的，流过管道的水是各自的
- 类比：这不是 SaaS，是电饭煲。锅是买的，饭是你自己的

## 第二条 · 默认即私密

- 提取、蒸馏、渲染，全部本地进程，**零外联**（不请求任何 API、不打日志到外面）
- 画像按敏感度分层（public / private），**默认 private**；要公开必须用户主动选
- 分享功能（如导出 Wrapped 页）必须先过脱敏（redact 清单），且导出前给用户看"即将分享的内容清单"
- 违反第一/第二条的 PR 一律不合并，无论多好用

## 第三条 · 探测不硬编码

- 不预设"用户机器长什么样"：agent 存档位置用探测（路径模式表）而不是写死的绝对路径
- 探测不到的 agent 明确报告"没找到，跳过"，绝不静默失败，绝不替用户猜
- 新 agent 支持 = 配置表加一行，不需要改代码

## 第四条 · 说人话（继承自项目起源）

- 一切面向用户的命名和文案，用用户自己会说的话（本项目 35 次"说人话"换来的教训）
- 成文规则见 engine/SOP_蒸馏流程.md 第一条

## 第五条 · 可再生

- 任何产物都能由"数据 + 脚本 + SOP"重新生成；手编产物必须在 manifest 登记
- 自检（engine/self_check.py）全绿才允许 commit

---

## 为什么这么定（背景）

2026-08-31 与用户讨论产品化时的原话：

> "肯定不愿意啊 必须要注重个人隐私 每个人自己跑自己的"

这就是宪法第一条的来源。当时画像里躺着真实姓名、年龄、政治面貌、薪资、家人姓名——给自己用没问题，但如果别人装了这个 skill 而隐私边界没设计好，等于把最敏感的自我画像默认交出去。

**对照开源同类**：memU（14k★）形态最像但走云端同步——"跨设备同步"的便利换来的是数据上他们的服务器。言镜的差异化定位恰恰是：**功能可以少，隐私一步不让。** 这不是营销话术，是架构决定。
