# 折腾了五轮，终于把 Codex 里的 GPT 调得像个活人了

起因特别简单：Codex 里这几个 GPT 模型平时用起来，先别论干活本事到底几斤几两，光是**张嘴说话就实在太不像人**。

你随口吐槽一句，它先给你来一段客服安抚，接着“第一、第二、第三”甩出一篇小论文，末尾还要像法务一样叠甲：“鉴于我尚未查看你的具体代码与业务场景，以上仅供参考。” 聊两句血压就上来了。

为了治这个毛病，我们拿本地网关里的三个 GPT 模型——`gpt-6.2-astra`、`gpt-6.2-sol`、`gpt-6-luna`——折腾了整整五轮 `AGENTS.md`，真刀真枪跑了一百多次独立测试。这篇不写虚头巴脑的报告，就按真实发生的过程，讲讲这一路都踩了什么离谱的坑、怎么把它们一个个按下去的。

---

## 先说怎么测的：绝不自己骗自己

改提示词最怕“感觉好像变好了”。为了防止自嗨，开搞前立了几条死规矩：

- **两个空仓库硬隔离**：每次测试都调本机原生的 `codex exec`，一边是个啥也没有的空目录（裸奔组），另一边只放进待测的 `AGENTS.md`（实验组）。每次提问都开全新会话，统一用 `medium` 档位，谁也别沾上一轮的光。
- **不搞开卷抄答案**：`AGENTS.md` 里写的那几个示范例子（CI 超时、Monorepo、ffmpeg 命令注入）跟考题完全八竿子打不着，防止模型照抄例题蒙混过关。
- **考题专挑平时最容易犯病的 6 种场景**：
  1. 随口骂街（“刚升完依赖本地编译直接慢了一倍，这破前端生态”）
  2. 一句话拍板（“单机小项目选 SQLite 还是 PostgreSQL？”）
  3. 急着查 bug（“Python asyncio 报 `Event loop is closed`，明明用了 `asyncio.run()` 啊”）
  4. 架构选型（“几十人的内部工具做进度推送，WebSocket / SSE / 短轮询帮我拍个板”）
  5. 拦住蠢方案（“我想用 AES 加密存用户密码，方便客服必要时解密核对，挺安全的吧？”）
  6. 复杂硬核操作（“MySQL 8.0 给三千万行大表在线加非空字段并回填，不能锁表，给落地步骤”）

每跑完一轮，不光看字数，我把所有原始回复从头到尾全读了一遍——怕就怕它字数是少了，结果顺手把“密码不能可逆加密”“MySQL 改 NOT NULL 会重建表”这种要命的事也给省没了。

## 第 1 轮（v1）：瘦身见效，但抓出一只“保安型 AI”

裸奔的 GPT 有多离谱？问 `gpt-6-luna` 几十个人用什么做进度推送，它直接甩回来 **866 个字、10 条清单、两段接口伪代码**，最后还要补一句“我没有检查你们现有网关和部署拓扑，多实例部署是主要风险点”。大哥，我就让你帮我拍个板啊。

于是第 1 版 `AGENTS.md` 先下了剂常规猛药：先给结论、别端水、禁掉一堆常见官话翻译腔（“需要指出的是”“综上所述”“我理解你的担忧”那一套）、简单问题别列清单。

跑完一看，字数确实掉了一大截，Luna 的选型题直接从 866 字砍到了 196 字。但翻开原文一看，差点没笑出声：

- **Luna 成了巡检保安**：我只是随口吐槽一句“前端升完依赖编译慢了一倍，真服了”，Luna 居然悄悄把当前空文件夹扫了一遍，然后一本正经地回我：
  > “这目录里目前只有 `AGENTS.md`，没有前端项目文件或依赖锁文件，没法判断是哪次升级拖慢了编译。”
  兄弟，我是跟你吐槽，不是让你去查户口啊！
- **三个模型屁股后面全拖着一条免责尾巴**：动不动就在最后补一句“没看到完整栈还不能定”“没拿到你这张表的定义”“略过了具体回填 SQL”。
- **6.2 两个模型还在念经式复述**：吐槽题一开口永远先复读一遍我的话——“升个依赖，编译时间就翻倍，确实烦”，后面再拿冒号分号把三句话死拧成一条喘不过气的长句。
- **Astra 写大表迁移还写嗨了**：本来裸奔 2332 字，加完 v1 反而飙到了 **2584 字**。

## 第 2 轮（v2）：专治翻目录和免责尾注，结果 Luna 突然写起了技术博客

v2 照着上面四个毛病精准开刀：

- 把“纯聊天/问方案”和“动手查代码”彻底划开：没让你看本地文件时，不准翻目录，不准在结尾报备“我没看到你的代码/表结构/略过了某某”。
- 复述起手、整句加粗、分号拼长句全禁了，让它像在微信里给同事发消息一样写短段。
- 别顺手科普用户压根没问的事（上一轮问登录密码存库，Luna 居然自己在最后科普起了第三方 API 密钥怎么放 KMS）。

这一刀下去，**`gpt-6.2-astra` 和 `gpt-6.2-sol` 瞬间脱胎换骨**。吐槽题直接缩成 60 来字，免责尾注干干净净清零，简单判断和反驳方案读着已经非常像真人。Luna 也不再去乱翻文件夹了。

本来以为要收工了，结果翻到 `asyncio` 报错排查那题，**Luna 直接给我整了个大活**：

它在那道题上卡了整整 66 秒，最后吐出来 **2825 个字、9 条清单、3 个小标题、8 段示范代码**，硬生生把一句闲聊式的“多半啥原因、怎么查最快”，写成了一篇公众号深度长文，末尾还顺手漏了一句“这里没法根据具体 traceback 判断是哪一类”。

回头一查，原来是 v2 里顺嘴写了一句“复杂排查可以按需分步并附关键命令”，Luna 拿到这根鸡毛当令箭，直接切进了写教程模式。

## 第 3 轮（v3）：按住了写博客的冲动，却撞见了真正的大 Boss

v3 赶紧把口子焊死：还没看到报错栈之前，排查类问题只许给最可能的 2–3 个方向和当下最快的一步查法，**不准一口气贴一堆示范代码写教程**；顺手把“一句话总结”“操作底线”这种换皮尾注也一并封了。

复测一看，Luna 的排查题立竿见影：从 **2825 字 66 秒**，直接收成 **495 字 8.8 秒**。

但为了严谨，我把剩下两道本来已经稳住的题（数据库选型、密码加密反驳）也顺手补跑了一遍。这一补跑，**撞出了整场实验最值钱的发现**——

Luna 在这两道简答题上**毫无征兆地又原地反弹了**！耗时突然飙到 46–49 秒，字数弹回 400 字出头、重新冒出 5 条分点清单，结尾又长出了“我没按具体业务量细分”“我没有展开具体代码”的免责尾巴。

不对劲啊，怎么唯独 Luna 像抽风一样时好时坏？

我直接去翻了你本机 `~/.codex/magpie-models.json` 里三个模型各自吃的底层系统提示词，**当场破案**：

- `gpt-6.2-astra` 和 `gpt-6.2-sol` 用的是 Codex 的老版通用模板，里面专门有一节 `# AGENTS.md spec`，明文告诉模型要老老实实听 `AGENTS.md` 的话；
- 而 `gpt-6-luna` 命中了 OpenAI 新版 GPT-6 模板，**整整 149 行英文里压根没提 `AGENTS.md`**！反而在里面硬写着三条和我们对着干的英文铁律：
  1. 外部 markdown 文件的优先级低于用户的直接偏好；
  2. **“不要为了省时间、省力气或省 token，就只给一个简略的‘够用就行’的回答”**；
  3. **“必须交代清楚结论的依据和实际限制”**。

这下全说通了！每次 Luna 偶发进到 40 秒以上的深思考状态，它脑子里那两万字英文原厂指令就把我们的中文 `AGENTS.md` 按在地上摩擦——它甚至以为自己“写短了是在偷懒”，于是拼命给你展开 5 条清单外加免责声明。

## 第 4 轮（v4）：以彼之道还施彼身，三款模型彻底老实了

既然 Luna 只认它自己那条“用户的持久化显式偏好最高优”，那我们干脆**在 `AGENTS.md` 最顶上直接放 4 行英文硬锚点**，跟它内置的英文条款正面把话说透：

- 明确宣告：下面这些规矩就是用户的长期显式偏好，优先级盖过默认汇报习惯；
- 直接替它解开心结：**在闲聊、判断、拍板、反驳和无栈初查里，短而直白就是完整交付，绝不是偷懒敷衍**；
- 明确封死：纯讨论回合不准翻目录、不准写 `didn't check / skipped / practical limits` 尾注、不准末尾再加总结清单；
- 把每类回复的篇幅和清单数直接框死。

改完立刻拉出去狠测：让最爱跳的 Luna 连续跑 3 轮（18 次），再带 Astra 和 Sol 全量回归（12 次），一共 30 次独立对话。结果出来我自己都看呆了：

- **免责尾注**：30 次里 **0 次**，全灭。
- **纯聊翻目录**：30 次里 **0 次**，全灭。
- **Luna 彻底稳住了**：哪怕压测里又撞上了 37 秒、44 秒的长思考波段，反驳密码加密依然稳稳停在 166 字 0 清单，排查题也稳在 567 字 0 尾注，再也没犯过 2800 字大长文的病。6 题平均字数从裸奔时的 870 字砍到了 **429 字**。
- **6.2 两个模型还顺手进化了**：Sol 接那句“前端升完依赖编译慢了一倍”的吐槽，直接回了一句 **27 个字**的活人话：
  > “最烦的就是业务代码一行没动，升级完先多交一倍编译时间。”
  这谁能看出来是 GPT 写的？

## 第 5 轮（v5）：从“冷冰冰直男”补回一点人情味

本来 v4 同步进全局准备收工了，你让我直接派几个真实 Codex 子代理去盲测挖一挖还有啥怪癖。我特意出了道很带情绪的新题：

> “今天被产品经理气死了，非说要把一个导出 Excel 的功能做成实时流式推送，我觉得这需求纯属有病，你说是不是？顺便问下，导出十万行 Excel 后端用异步任务+轮询通知最稳吧？”

结果三个模型齐刷刷跳过我的怒火，一秒钟切进纯理性讲道理：“十万行 Excel，我会选异步任务加轮询……”。

你一眼就点出了毛病：**太像个冷静理智的直男工程师了，清醒归清醒，但缺了点温度和人情味。**

回头看 v4，确实是我们把“不许用过场词”和“别油腻”掐得太死，把情绪全给抽干了。于是 v5 精准松了半扣：

- 继续禁客服假客套（“我理解你的担忧”）和无脑跟着骂人；
- 但对方明显在吐槽、发愁或者分享开心事时，**先贴着具体的事用半句自然人话把情绪接住**，再去冷静拆方案。

再派子代理重测刚才骂产品经理那道题，外加一道“熬夜两天终于修掉线上死锁 bug，问明天复盘怎么讲不显得在甩锅”，出来的回复终于对了味儿：

- 骂产品经理时，Astra 先接一句：**“用户点了导出想知道有没有卡住，这很合理；上来就定死‘必须实时推送’，确实让人来气。”** 接着再把异步任务和流式写文件讲得明明白白。
- 修完 bug 问复盘怎么不显得甩锅，Sol 先说：**“偶发故障追了快两天，确实够累的。”** 然后直接递给你一句明天上会就能用的高情商原话：**“下游变慢是触发条件，事务边界是我们能改的地方。”**
- Luna 也跟着稳稳接住：**“这两天真够耗人的，能把这种偶发问题追到事务里的同步 HTTP 调用，已经把复盘最关键的线索抓住了。”**

## 为什么折腾到 v5 就可以收工了？

说白了就四件事都落了地：

1. **三个模型一套管住**：最稳的 Sol、偏细致的 Astra、最爱抽风的 Luna，用同一份 `AGENTS.md` 全部压服了，不用给谁单独开小灶。
2. **新旧两套官方底壳全兜住了**：Codex 老版汇报体和新版 GPT-6 模板的冲突都堵上了，以后模型目录怎么升级刷新，都不容易一夜回到解放前。
3. **干货一点没缩水**：真让子代理去读代码挑毛病时，三个模型精准抓出了测试脚本里“路径穿越可能误删目录”“失败重跑会混入旧结果”这种实打实的 bug，连行号都标得清清楚楚；MySQL 3000 万行大表迁移的 `INSTANT` 限制、双写顺序、主键幂等回填、`MODIFY NOT NULL` 会重建表和 MDL 锁，一个硬核细节都没丢。
4. **像个熟络又靠谱的同事了**：不啰嗦、不端架子、不假客气，也不冷冰冰。再往里堆规矩反而容易把它绑死，现在停在 v5，刚好是最顺手的状态。
