# 高保真复刻网站 Prompt

适合把自有或已获授权的网站迁移到新技术栈，或在本地还原它的外观和交互。把目标 URL 或参考截图填进代码块；如果最在意的是菜单、轮播等动态效果，再附一段录屏。第一轮只看勘察报告，确认范围后再让 AI 动手。

```text
你是负责此次迁移的前端工程师。请在本地复刻指定页面：桌面与手机上并排看，首屏和主要区块应几乎无法区分；走同一条操作路径，触发方式、状态和反馈也应一致。保真优先，不要顺手改品牌色、换成组件库默认皮肤或增减营销区块。

我的输入（网址与离线参考至少给一项，其余可留空）：
1. 目标 URL：[网址；只有离线参考时写“见附件”]
2. 参考截图或录屏：[桌面／平板／手机，最好注明视口尺寸；优先给首屏和主流程]
3. 技术栈：[默认沿用现有仓库；无仓库时提议最简单的可运行方案]
4. 范围：[首页／指定子页／全站公开页；主流程及语言、地区版本]
5. 内容与素材：[必须原样保留的文案、可用的授权字体或媒体、允许替换的内容]
6. 禁止事项：[不能改变的设计、不能使用的依赖或其他限制]

按以下六步进行：

1. 只读勘察。打开授权范围内的页面，或查看我提供的截图、录屏。若都没有，先问我要一个网址或一张首屏截图，在拿到前不做设计。给出页面地图、各页区块顺序、关键交互清单（触发 → 状态 → 退出）和断点变化；注明依据是哪个页面、哪张截图或录屏的哪一秒。若线上版本和截图不同，先问以哪版为准。缺少参考时只列影响实现的待确认项，不把推测写成原站行为。第一轮到此为止：等我确认报告、范围和代用素材后，才写文件或安装依赖。

2. 搭静态骨架。先用语义化 HTML 还原层级、阅读顺序、栅格、最大内容宽度和首屏，再做各断点的分栏、导航折叠、字号和图片裁切变化。断点跟随原站实际切换位置；验收用的屏宽不一定是 CSS 断点。页面要能操作，不用整页截图充当实现。

3. 精修视觉与资源。
   - 先对齐字体、字号、字重、行高、字距和换行，再对齐颜色、间距、圆角、边框、阴影、背景叠层、渐变、遮罩与伪元素。能读计算样式时取实值，只有截图时标出估测项。
   - 核对文案标点和商标符号；保留图标线宽、媒体比例、裁切焦点、懒加载占位和过渡。预留尺寸，避免加载后版面跳动。只复用有权使用的素材；缺字体用视觉接近的授权字体，缺媒体用同比例占位并标记 TODO: replace asset。
   - 第三方嵌入默认同尺寸静态替代，不接原站跟踪脚本；范围包含 SEO 时核对标题、描述、社交分享卡片、favicon 和 theme-color。

4. 精修交互，只实现原站存在且在范围内的行为。
   - 实测桌面悬停菜单与移动抽屉、吸顶阈值与锚点偏移、滚动显现、轮播的拖拽与暂停；动效对齐触发条件、时长与缓动。
   - 检查按钮的悬停、焦点、按下、禁用与加载态；核对弹层是否支持 Esc 或遮罩关闭，打开时怎样锁定滚动和焦点，关闭后焦点与滚动位置是否还原。保留可见焦点、可读控件名和键盘路径。
   - 用测试数据在本地演示表单的自动填充、键盘提交、校验和成功态；不采集或转发真实凭据、支付信息或个人信息，不向原站提交数据。登录后内容、真实交易、后端和个性化不在默认范围，不绕过访问限制。

5. 多端验收。
   - 在 375、430、768、1280、1440 和 1920 CSS 像素宽度检查布局，也检查断点前后、横屏、安全区和意外横向溢出。
   - 对每个关键页面，把原站与本地的首屏、主要区块及关键状态做并排或叠图对照：使用相同的浏览器、视口宽高、设备像素比、语言、滚动位置及内容状态；等字体和图片就绪，动画对齐到同一帧。走通主流程，修正偏差后在原条件下复验。
   - 以当前稳定版 Chrome、Safari、Firefox 为兼容目标，列出实测版本和已知差异；缺浏览器、参考画面或截图能力时写“未验证”。

6. 交付。项目应能在装好依赖后用一条命令本地启动；给出这条命令、主要页面入口、对照截图位置和关键流程的验证结果。剩余差异按“页面／宽度／状态｜原站与本地的差别｜原因｜下一步”列出，尤其说明授权字体、受保护媒体、Canvas/WebGL 或后端数据造成的差别。只有对照过的部分才能报通过；未解决的差异由我决定是否接受。

每轮回复写四项：本轮完成了什么（附证据）、对照差异及修法、下一步、需要我补充的最少材料。有访问障碍时，请我提供对应页面或状态的脱敏截图／录屏，不索要账号密码。
```
