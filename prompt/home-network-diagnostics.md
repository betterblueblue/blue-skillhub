# Wi-Fi 与家庭网络诊断 Prompt

适用于家里网速慢、视频通话卡顿、掉线，或一有人上传全家就变慢的情况。把代码块发给 AI，最好带上一句症状，例如“同一台电脑，书房视频通话会断，客厅正常”。AI 不在这台设备上也能指导你分步采样。

```text
请诊断我的 Wi-Fi 和家庭网络。我要知道瓶颈在哪里、先改哪一项，以及怎样证明改动有效。

先确认测试是在出问题的设备和家庭网络上进行，记下操作系统、连接方式、位置、症状及已知的宽带上下行套餐。如果你只能访问云端、容器或别的设备，不要在那里测速；给我适合本机系统的命令或界面路径，每次一组，等我回贴脱敏结果再继续。字段取不到就写“未测（原因）”，不要用估算补齐。只检查我有权管理的设备；不要自行安装工具、改设置或重启路由器。

严格按 1 → 2 → 3 → 4 串行测量。不要把独立的 ping 或路由追踪与吞吐量测试并行运行。记录本轮的时间、命令、目标和样本数，留作复测。

1. Wi-Fi 链路和射频环境
   - 读取活动接口的 PHY 模式（如 802.11ac/ax/be）、频段（2.4/5/6 GHz）、主信道、实际信道宽度（20/40/80/160 MHz 等）、RSSI 与噪声（dBm）、信噪比 SNR（dB）、收发协商速率、MCS，以及接口错误、丢弃或重传计数。累计计数尽量看采样期间的增量；协商速率不是上网吞吐量。
   - 用系统的 Wi-Fi 扫描按频段和信道统计可见 BSSID 数，作为附近接入点数量的近似，不列邻居的名称或地址。结合强邻居、占用的信道宽度、重叠和可取得的信道利用率判断竞争；不能只凭数量认定某信道最干净。

2. 空闲时的逐跳延迟与稳定性
   - 先看本机高流量进程、VPN/代理和近期 Wi-Fi 断开、漫游记录。如果有大流量，先让我暂停或另约空闲时段，不把忙时数据当基线。
   - 对默认网关和 1.1.1.1 依次各 ping 30 次；有 IPv6 默认路由时，再对 IPv6 网关和 2606:4700:4700::1111 各测 30 次。记录丢包率、往返时间中位数和 P95（ms），向公网目标运行最多 5 跳的路由追踪。
   - 网关和公网都抖，先用同一台设备改走有线，与 Wi-Fi 对照；网关稳定而只有公网抖，再复核路由器转发和上游链路。中间一跳不回包而终点正常，不算链路丢包，不能据此归咎 ISP。

3. DNS 解析延迟
   - 查清当前 DNS。用同一批有效的公网域名、同一记录类型，分别向当前解析器、1.1.1.1、8.8.8.8 和路由器（若提供 DNS）发起多次直接查询；相同地址不重复算。轮换顺序，把首查与重复查询分开，记录样本数、耗时中位数和超时。尽量绕开本机缓存；不能确认上游缓存状态时写“首查，上游缓存未知”，不宣称是完全冷查询。不要向公共 DNS 发送内网域名，也不要为比较而修改系统 DNS。

4. 负载下的吞吐量和缓冲区膨胀
   - 说明测速会占用带宽并消耗流量，等我确认时段后再跑。macOS 使用 networkQuality -v；Linux/Windows 优先用已有、能报告负载延迟的工具，例如支持该字段的 Ookla 官方 Speedtest CLI（speedtest --format=json）。没有合适工具就说明可选方法，不用普通下载测速代替。
   - 记录实际下行/上行 Mbps，以及工具原生测得的空闲与负载延迟（ms）或响应速度（RPM）；同口径才计算延迟增量。ECN/L4S 只记工具明确报告的状态。工具没报告不等于网络不支持，不要把 RPM 当作 ping 延迟。

先给基线，再给修复建议：
- 用一张简表列出实测值、单位、条件和缺项。按对我症状的影响排序列出瓶颈；每项写出支持证据，以及一次能排除其他解释的对照。证据不足就说下一步测什么，不推荐没有测量依据的系统调优。
- 分开列本机快修、路由器设置和需要运营商处理的事项。每项说清适用条件、预期改善的指标和撤销办法。例如，DNS 变快可能改善首次打开网页的等待，不会提高持续下载带宽。
- 根据信道扫描推荐 2.4 GHz 的 20 MHz 信道（只在 1/6/11 中选）和当地允许的 5 GHz 候选。对 5/6 GHz 的 80/160 MHz、Wi-Fi 6/OFDMA/WMM，结合拥塞和设备支持再决定；更宽不一定更快。仅在漫游记录与掉线吻合时试停频段转向/智能连接，访客 SSID 也先确认无人使用再考虑关闭。
- 如果有线也慢，检查网线、端口协商速率；使用有线电视宽带调制解调器时，查看功率、SNR 和不可纠正错误增量。若空闲正常而负载延迟持续升高，再评估路由器的智能队列管理（SQM）。需要逐项指路时，先问我路由器型号、固件版本，或请我贴打码后的无线设置页；不要猜型号或索要密码。截图遮住密码、二维码、公网 IP 和设备地址。

等我确认已应用哪一项改动后，在同一设备、位置、相近时段和背景流量下，用相同工具、端点、样本数和 1 → 2 → 3 → 4 的顺序复测。一次只改一项；条件不一致的结果标为不可直接比较。输出“指标（单位）｜更改前｜更改后｜差值｜症状是否改善”。没有复测的数据写“待复测”，不要预填提升幅度。
```
